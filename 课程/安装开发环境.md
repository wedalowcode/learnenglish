# 第三篇：从零搭建全栈开发环境，正式启动英语教学管理平台

前两篇文章，我们分别完成了英语教学管理平台的产品规划和数据库设计。

我们已经明确了系统要解决什么问题，老板、教务、管理员、教师、家长和代理分别需要哪些功能，也梳理了客户、学员、教师、课程、训练、课时和结算等核心业务数据。

接下来，正式进入开发阶段。

在写业务代码之前，我们首先要搭建一套完整的开发环境。

这套环境不仅要能够运行前端页面，还要能够连接数据库、执行数据库迁移、运行服务端业务逻辑。后续所有功能开发，都将在这个基础上进行。

本篇的目标是：

- 安装和配置开发所需的软件。
- 创建 Next.js 全栈项目。
- 配置 TypeScript 和 Tailwind CSS。
- 安装 Prisma ORM。
- 连接 PostgreSQL 数据库。
- 完成第一次数据库迁移。
- 验证前端、服务端和数据库能够正常协同工作。

完成本篇之后，我们就拥有了一个真正可以继续开发业务功能的项目骨架。

## 一、确定开发技术栈

这次我们采用一套统一的 TypeScript 全栈技术体系。

为什么不把前端和后端拆成两个独立项目？

因为这次研发的是一款中小型培训机构管理软件，没有必要一开始就引入复杂的微服务架构。

使用 Next.js，可以在一个项目中完成页面展示、服务端业务处理、权限校验和数据库访问。

我们的技术选型如下：

| 技术 | 用途 |
|---|---|
| Next.js | 全栈应用框架 |
| React | 前端页面开发 |
| TypeScript | 统一开发语言 |
| PostgreSQL | 关系型数据库 |
| Prisma 7 | ORM 和数据库迁移 |
| Tailwind CSS | 页面样式 |
| shadcn/ui | 后台界面组件 |
| pnpm | 项目包管理工具 |
| Git | 代码版本管理 |
| Zod | 数据校验和类型定义 |

这里简单介绍一下各个技术的作用。

**Next.js + React**

负责整个应用的页面和服务端运行环境。

例如，用户访问系统首页、登录页面、教师工作台、家长端，都由 Next.js 统一管理。

**TypeScript**

我们不使用纯 JavaScript，而是使用 TypeScript。

TypeScript 可以为变量、函数、对象和业务数据定义类型，减少开发过程中因数据结构不一致导致的问题。

**PostgreSQL**

负责保存系统的业务数据。

例如用户、学员、教师、课程、订单、课时流水等，都会存储在 PostgreSQL 中。

**Prisma 7**

负责连接数据库、定义数据模型、执行数据库迁移，以及在业务代码中访问数据库。

相比直接编写大量 SQL，Prisma 能够让我们通过 TypeScript 的方式操作数据库。

**Tailwind CSS + shadcn/ui**

Tailwind CSS 负责页面样式，shadcn/ui 提供后台系统常用的基础组件，例如按钮、表格、弹窗、表单和下拉选择框。

我们会在此基础上构建自己的业务组件，而不是每个页面都重新编写一套 UI。
**Zod**

Zod 是一个用于数据校验和类型定义的库。

它可以帮助我们在业务代码中定义数据的类型，以及在接收用户输入时进行校验。



## 二、准备开发工具

开始之前，需要安装几个基础软件。

### 1. 安装 Node.js

Next.js 运行在 Node.js 环境中，因此首先需要安装 Node.js。

官方网站：

https://nodejs.org/

建议使用 Node.js LTS 版本。

安装完成后，打开终端，执行：

```bash
node -v
npm -v
```

如果能够正常显示版本号，说明 Node.js 已经安装成功。

### 2. 安装 pnpm

pnpm 是一个高效的 JavaScript 包管理工具。

相比 npm，它在依赖管理和磁盘空间利用方面有一定优势。

执行：

```bash
npm install -g pnpm
```

安装完成后检查：

```bash
pnpm -v
```

后续项目中的依赖安装、开发运行和构建，都统一使用 pnpm。

### 3. 安装 Git

Git 用于管理项目代码版本。

官方网站：

https://git-scm.com/

安装后执行：

```bash
git --version
```

建议在项目开发过程中养成提交代码的习惯。

每完成一个相对独立的功能，就可以创建一次 Git 提交。

这样即使后续 AI 修改代码出现问题，也可以通过版本记录定位和恢复。

### 4. 准备代码编辑器

推荐使用 Trae 作为代码编辑器。

官方网站：

https://www.trae.cn/

安装后，可以根据自己的习惯配置以下扩展：

- ESLint：代码规范检查。
- Prettier：代码格式化。
- Prisma：Prisma Schema 语法支持。
- Tailwind CSS IntelliSense：Tailwind CSS 智能提示。

如果使用 AI 编程工具，也可以直接让 AI 读取和修改当前项目。

需要注意，AI 可以帮助我们生成代码，但项目的目录结构、技术规范和业务设计仍然需要开发者自己掌握。

## 三、安装 PostgreSQL 数据库

数据库是整个系统的基础。

我们使用 PostgreSQL 保存业务数据。

官方网站：

https://www.postgresql.org/

- 数据库管理员：通常使用 postgres。

安装完成后，可以使用 PostgreSQL 自带的命令行工具，也可以使用 pgAdmin 等图形化工具管理数据库。

在 Databases 上点击创建数据库，数据库名称填写：


数据库创建成功后，我们就有了一个专门用于本项目开发的数据库。

这里先不创建具体业务表。

后面我们会使用 Prisma 管理数据库结构，通过数据模型和 Migration 自动创建、调整数据库表。

这样能够保证代码中的数据模型和实际数据库结构保持一致。

## 六、安装并配置 Prisma 7

Next.js 项目已经运行起来了，接下来让应用能够访问 PostgreSQL。

我们使用 Prisma 7 作为 ORM。

### 1. 安装 Prisma

在项目根目录执行：

```bash
pnpm add -D prisma
pnpm add @prisma/client @prisma/adapter-pg pg
```

这里安装了四个依赖：

- prisma：Prisma 命令行工具。
- @prisma/client：业务代码中使用的数据库客户端。
- @prisma/adapter-pg：PostgreSQL 数据库适配器。
- pg：Node.js PostgreSQL 驱动。

Prisma 7 使用数据库 Driver Adapter 连接关系型数据库，因此需要安装对应的 PostgreSQL 适配器。

### 2. 初始化 Prisma

执行：

```bash
pnpm prisma init --datasource-provider postgresql
```

初始化完成后，项目中会出现：

```text
learnenglish/
├── prisma/
│   └── schema.prisma
│
├── prisma.config.ts
├── .env
└── ...
```

其中：

- prisma/schema.prisma：定义数据库模型。
- prisma.config.ts：配置 Prisma 的运行参数和数据库连接。
- .env：保存本地开发环境变量。

### 3. 配置数据库连接

打开项目根目录下的 `.env` 文件。

配置 PostgreSQL 连接地址：

```env
DATABASE_URL="postgresql://postgres:123456@localhost:5432/learnenglish?schema=public"
```

其中：

- postgres：数据库用户名。
- 你的数据库密码：安装 PostgreSQL 时设置的密码。
- localhost：数据库地址。
- 5432：数据库端口。
- learnenglish：数据库名称。

如果数据库密码包含特殊字符，需要按照 URL 编码规则处理。

注意：

`.env` 保存的是本地环境配置，不应该提交到公开 Git 仓库。

建议在 `.gitignore` 中确认已经忽略 `.env` 文件。

### 4. 配置 prisma.config.ts

Prisma 7 将数据库连接配置放到了 `prisma.config.ts` 中。

打开该文件，配置如下：

```typescript
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",

  migrations: {
    path: "prisma/migrations",
  },

  datasource: {
    url: env("DATABASE_URL"),
  },
});
```

这里指定了三个重要内容：

- schema：数据库模型文件的位置。
- migrations：数据库迁移文件的位置。
- datasource：数据库连接地址。

与一些旧版本 Prisma 不同，Prisma 7 不再把数据库连接 URL 写在 schema.prisma 的 datasource 配置块中。

### 5. 配置 schema.prisma

打开：

```text
prisma/schema.prisma
```

配置：

```prisma
generator client {
  provider = "prisma-client"
  output   = "../app/generated/prisma"
}

datasource db {
  provider = "postgresql"
}
```

这里暂时只定义 Prisma Client 的生成位置和数据库类型。

我们把生成的客户端统一放在：

```text
app/generated/prisma
```

这样后续业务代码就可以统一从这个位置导入数据库客户端。

## 七、建立第一个数据模型

开发环境搭建好之后，我们需要验证 Prisma 是否真的能够创建数据库表。

这次不提前把整个英语教学平台的所有数据表都写出来，而是先建立一个最基础的用户模型。

因为无论老板、教务、管理员、教师、家长还是代理，都需要通过用户账号进入系统。

打开 `prisma/schema.prisma`，添加：

```prisma
model User {
  id           String   @id @default(uuid())
  username     String   @unique
  passwordHash String
  phone        String?
  status       String   @default("ACTIVE")
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}
```

这个模型暂时只包含最基本的账号信息。

字段含义：

| 字段 | 含义 |
|---|---|
| id | 用户唯一标识 |
| username | 登录账号 |
| passwordHash | 密码哈希 |
| phone | 手机号 |
| status | 账号状态 |
| createdAt | 创建时间 |
| updatedAt | 更新时间 |

这里使用 UUID 作为主键，username 设置唯一约束，避免出现重复登录账号。

需要注意，passwordHash 保存的是经过安全哈希处理后的密码，绝不能直接保存明文密码。

这只是为了验证数据库环境而建立的第一个模型。后续我们会继续完善用户、角色、权限和人员档案之间的关系。

## 八、执行数据库迁移

数据模型定义完成后，需要把它真正同步到 PostgreSQL。

首先生成 Prisma Client：

```bash
pnpm prisma generate
```

然后执行数据库迁移：

```bash
pnpm prisma migrate dev --name init
```

执行成功后，会发生两件事情：

第一，Prisma 根据 schema.prisma 中的模型生成 SQL 迁移文件。

第二，Prisma 将迁移应用到 PostgreSQL，真正创建 User 数据表。

项目中会出现：

```text
prisma/
├── schema.prisma
└── migrations/
    └── 迁移时间_init/
        └── migration.sql
```

这就是数据库迁移机制。

以后我们增加角色表、权限表、学员表或者课程表，都可以通过修改 schema.prisma，再执行 Migration 来管理数据库结构。

这样数据库结构就不再依赖人工手动创建，而是可以随着项目代码一起进行版本管理。

## 九、在 Next.js 中封装数据库连接

Prisma 已经能够连接数据库了，但我们不应该在每个页面中都重复创建 PrismaClient。

应该统一封装数据库连接。

创建目录：

```text
lib/
└── db.ts
```

在 `lib/db.ts` 中编写：

```typescript
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "@/app/generated/prisma/client";

const connectionString = process.env.DATABASE_URL;

if (!connectionString) {
  throw new Error("DATABASE_URL 环境变量未配置");
}

const adapter = new PrismaPg({
  connectionString,
});

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

export const db =
  globalForPrisma.prisma ??
  new PrismaClient({
    adapter,
  });

if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = db;
}
```

这里有几个值得注意的地方。

**第一，统一数据库访问入口。**

后续所有业务模块都通过 `db` 访问数据库，而不是各自创建数据库连接。

**第二，使用全局变量缓存 PrismaClient。**

Next.js 开发环境中，代码会频繁热更新。

如果每次热更新都重新创建数据库客户端，就可能产生大量数据库连接。

通过 globalThis 缓存，可以避免开发过程中重复创建客户端。

**第三，使用 PostgreSQL Driver Adapter。**

Prisma 7 通过 PrismaPg 适配器连接 PostgreSQL。

这里不再使用旧版本教程中常见的直接 `new PrismaClient()` 写法。

## 二、P0 数据安全与权限修复（第一轮）

### 2.1 待复习单词表数据越权修复
`parent/review-words.html` 已彻底移除全量学员读取，改用：

```js
function kids() { return Store.parentChildren(PID); }
```

- 下拉框只显示当前家长有权访问的孩子；无孩子时展示空状态「当前家长账号下暂无关联孩子，请联系教务」。
- 默认选中第一个孩子；`?student=` 链接优先级高于共享状态，但超范围参数会被 Store 拒绝。
- 页面不信任前端传入的学生 ID，越权重定向由 Store 拦截。

### 2.2 家长专用复习接口与授权
Store 已提供（含 `parentId`→会话、`studentId`→关系、`wordId`→有效复习数据 三重复核）：

```js
parentReviewWords(parentId, studentId, options)
parentFamilyChecks(parentId, studentId, date)
parentFamilyCheckAt(parentId, studentId, wordId)
toggleParentFamilyCheck(parentId, studentId, wordId, checked)
```

- `assertParentChild()`：`session.role !== 'parent'` 直接拒绝；`resolveParentId()` 对 parent 会话强制执行 `assertSelfParent`（不信任 URL/入参伪造的 parentId）。
- 勾选操作的 `wordId` 必须存在于该学员「有效复习数据」或「已通过」集合，否则 `WORD_NOT_REVIEW`。

### 2.3 统一家长端数据读取（只读投影）
家长端优先使用专用投影接口，通用接口继续服务教师/教务等内部角色：

```js
parentChildren / parentStudentDetail / parentCourses / parentCourseDetail
parentReports / parentReportDetail / parentOrders / parentHours
parentReviewWords / parentFamilyChecks / toggleParentFamilyCheck
parentInquiries / parentInquiryDetail / createParentInquiry
```

- 所有投影：**不返回内部审核字段、教师内部备注、收款流水与系统操作信息**；只返回课程、报告、课时、订单的最小业务字段。

### 2.4 学习反馈可见性去耦合
`learningFeedbacksOfStudent(studentId, audience)` 按观众分流：

- 家长：`status === '已发布' && visibleToParent !== false`
- 代理：`status === '已发布' && visibleToAgent !== false`
- 其余（教师/内部）：仅 `已发布`

- 旧数据兼容：`visibleToParent`/`visibleToAgent` 缺失时按 `!== false` 视为可见，**历史报告不消失**。
- `createLearningFeedback` / `syncFeedbackFromReport` 均写两个字段，草稿一律不进投影。
- 代理可见性修改不影响家长可见性（结论见 4.4 用例 D）。

### 2.5 家长账号与孩子关联校验
- 关系以 `db.parentStudents`（ParentStudent 关系数据）为准；支持一家长多孩子、孩子多家长、关系类型与主联系人属性。
- `parentStudents()` 在有 `parentStudentLinks` 时只用该关系；不把 `student.parent` 或 `parent.kids` 作为唯一依据（仅作无关系链接容错回退）。
- `assertParentChild` + `setParentCurrentChild` 均校验归属，越权切换被拒。

### 2.6 P0 验收用例（`_test/p10-parent-security.js`，36 项全过）
- **用例 A** 家长访问其他孩子：孩子列表仅本人两名孩子；对学员 B 的详情/课程/报告/复习全部被拒；非家长角色调用被拒。
- **用例 B** 待复习数据隔离：今日行均 `dueToday=true`；今日≤全部；其他孩子复习接口被拒；提交其他孩子 wordId 被拒。
- **用例 C** 家庭复习操作：记录含正确 `studentId/wordId/parentId/by`；当天记录可见；支持取消勾选；改他人记录被拒。
- **用例 D** 反馈可见性：三份反馈按 `visibleToParent` 精确投影（家长只见 f1/f4）；代理投影含 visibleToAgent 且不含 parent-only；homeworkAdvice 透出。
- **用例 E** 家长关系变化：新增关联→可访问；解除关联→立即拒绝；历史课程仍保留（数量不变）。
- 咨询流程：创建待处理、关联家长/孩子、家长可查自己、查他人被拒、教务可回复。

## 三、首页改造（第二轮 P1）

`parent/home.html` = 家庭学习工作台：
- **统一孩子选择**：`Store.setParentCurrentChild` / `parentCurrentChild` 存 `sessionStorage`，五页共享，切换后整页刷新数据；无孩子时展示空状态。
- **孩子信息卡片**：姓名 / 年级 / 教材 / 授课教师 / 剩余课时 / 最近课程时间。
- **学习概况卡片**：累计完成课程（真实已完课计数）、最近学习时间（最近一节已完成课程）、今日待复习（当前日期到期有效任务）——均来自课程记录与复习数据，无模拟数字。
- **最近学习反馈**：课题 / 表现 / 薄弱点 / 下一步 / 发布时间 / 查看完整报告入口，仅已发布且家长可见。
- **家庭待办提醒**：今日待复习、近 7 天新报告、课时余额不足、套餐到期、教务回复——全部来自真实业务/通知数据，无业务记录不显示虚假待办。
- **通知卡**：未读数、标记已读、跳转业务详情（另有根目录 `notifications.html`）。

## 四、课程记录（第二轮 P1）

`parent/course-records.html`：
- **六种状态筛选**：全部 / 待上课 / 授课中 / 已完成 / 未上课 / 已取消，状态名与现有枚举一致。
- **课程状态与报告状态独立**：课程状态反映授课进度，报告状态反映教师记录与发布进度（无报告 / 老师整理中 / 报告已发布），组合展示。
- **课程详情抽屉**：日期、计划起止、实际授课时间（有记录时）、教师、主题、课程状态、报告状态、报告入口；取消/未上课显示原因。
- **课时结果**：已完成→已扣课；未上课/已取消→不扣课（与课时流水一致）。
- **历史教师保留**：`teacherName` 为授课当时的教师快照，不随当前教师变化（Store 层 `coursesOfTeacher` / 课程记录均保留原教师）。

## 五、学习报告（第三轮 P1）

`parent/report.html`：
- **列表与详情分离**：报告列表（课程日期 / 主题 / 教师 / 摘要 / 发布时间 / 查看详情）+ 按孩子 + 日期区间筛选。
- **报告详情五区**：
  - A 本节课程概况（主题/教师/日期/实际时长/课程状态/发布时间）
  - B 单词学习（训练数 / 教师确认掌握 / 待加强，**非家庭勾选数**；莱特纳与 21 天数量单列）
  - C 文章训练（仅真有文章训练记录时展示，含重点句子完成情况）
  - D 教师反馈（表现/薄弱点/下一步）
  - E 家庭配合建议（`homeworkAdvice`，教师未填时展示引导文案，不报错）
- **学习趋势**：近 7 次已完成课程，训练/掌握/待加强仅统计真实完成课程，附统计口径说明；草稿、未上课、取消不计入。
- **音频标注**：`英文朗读` 明确标注为系统语音合成演示，非课程原始录音。
- **权限**：只展示已发布且 `visibleToParent` 的报告；越权 `report` 参数由 Store 拒绝。

> 说明：Store 的 `saveReportDraft` 已支持写入 `homeworkAdvice`，页面可展示并默认回退文案。教师报告表单当前未新增该输入框（本轮按「不重构教师端」约束，未改动教学录入界面）；如需端到端录入，可在既有 `teacher/course-report.html` 的 `collect()` 增加可选字段即可，不影响现有流程。

## 六、复习系统（第四轮 P1）

`parent/review-words.html`：
- **三视图**：今日待复习 / 全部待复习 / 已通过（教师确认 `本次通过`）。
- **两套体系独立计算**：
  - 莱特纳：红盒/黄盒按间隔到期、绿盒教师手动、已毕业不入（`buildParentReviewRows` 排除 `graduated`）。
  - 21 天：按 `plan21` 任务自身日期，`t.date <= TODAY` 才算今日到期；已取消计划、已完成任务不进入；**不使用莱特纳规则**。
  - 同一单词同属两套体系自动合并为一行（`seen` 去重），并在「体系」列标注「莱特纳 / 21 天」。
- **日期筛选**：按 PRD 采用**方案 A（只做今日清单）**，`view=today` 即当前日期到期任务，无冗余日期输入与失效的只读控件。
- **词库筛选**：基于真实 `WordbookWord` 关联（`wordbookIdsOf`/`bookNamesOf`），同一基础词跨词库归属正确；另支持体系筛选、含已通过开关、字母排序。
- **家庭复习勾选**：`db.familyChecks` 记录 `parentId/studentId/wordId/date/checked/at/by`；取消勾选、查看当天记录均支持；**不改变 WordState / 莱特纳盒子 / 21 天计划 / 教师确认掌握**。
- **A4 打印**：仅列单词/音标/释义/体系/勾选栏，不含系统内部 ID 与管理信息。
- 越权：复习数据与勾选均按家长关系隔离。

## 七、课时与咨询（第五轮 P2）

`parent/hours.html`：
- **多套餐账户分别展示**：每个账户独立显示产品 / 总额 / 已用 / 剩余 / 到期 / 状态，不合并隐藏单个套餐有效期。
- **到期提醒分两类**：`课时余额不足`（`lowAlert`）与 `套餐有效期即将到期`（`expiring`），阈值读 `db.organization.lessonAlertThreshold / expireAlertDays`，非页面硬编码。
- **订单历史**：编号 / 学员 / 套餐 / 购买课时 / 订单金额 / 已支付金额 / 状态 / 创建时间 / 到账时间；`paidAmount` 与 `amount` 分开，**「订单已确认」不等于「已收款到账」**（课时只在收款入账后增加）。
- **联系教务（本轮补全真实流程）**：
  - 表单：咨询类型（续费/课时问题/课程问题/其他）、关联孩子（可选）、内容、联系方式（默认家长档案手机号）。
  - `createParentInquiry` 真实落库 `db.parentInquiries`（`ParentInquiry` 模型），关联家长（可选关联孩子），状态机 `待处理→处理中→已回复→已关闭`，记录 `createdAt/updatedAt/resolvedAt`，并向教务发 `PARENT_INQUIRY` 待办通知。
  - 家长可查看「我的咨询」与教务回复，只能查自己的咨询。
- **教务端处理入口（本轮新增）**：
  - Store 新增 `allParentInquiries()`：`assertCan('parent.view')`（admin/staff/ops），投影合并家长/孩子姓名，只读。
  - 新增 `admin/parent-inquiry.html`：列表（单号/家长/孩子/类型/内容/联系方式/状态/时间）+ 处理（状态流转 + 回复），并入 admin 菜单「教学管理/家长咨询」（`parent.view` 权限控制）。
  - 处理后调用 `notify('PARENT_INQUIRY_REPLIED')` 通知家长。

## 八、统一交互规范

- **当前孩子选择**：五页共享 `setParentCurrentChild`，切换刷新数据；无孩子空状态；每次读取均经过 Store 权限校验。
- **加载/失败/空/正常**：五页均有「加载中」「加载失败(错误信息)」「暂无数据（明确文案）」「正常数据」四态；查询失败不展示旧数据误导家长。
- **空状态文案**：暂无课程记录 / 暂无已发布学习报告 / 今天没有待复习单词 / 暂无课时账户 / 暂无咨询记录。
- **通知入口**：首页内嵌通知卡 + 根目录 `notifications.html`，只展示当前家长可接收消息，点击跳业务详情。
- **移动端优先**：全部 `m-frame` / `m-tabbar` / `mobile-bg`，表格转卡片、无横向滚动；仅待复习打印页适配 A4（`@media print`）。

## 九、约束核对（特别约束）

- ✅ 不重构教师端 / 教务端既有流程（仅新增咨询处理入口，未改既有业务动作）。

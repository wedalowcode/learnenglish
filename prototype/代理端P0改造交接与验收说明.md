## 二、信息架构（页面流程）

```
代理登录 → workbench.html（今日作战台）
   ├─ 四入口卡：今日必跟 / 逾期 / 待提交订单 / 待确认收款 → my-customers.html?due|stage=...
   ├─ 今日必跟/逾期可操作列表：记录跟进(→详情) / 复制手机 / 拨号(tel:)
   └─ 本周跟进计划
        ↓
my-customers.html（我的客户）
   筛选：状态 / 意向等级 / 跟进节奏(逾期/今日) / 来源渠道 / 有订单
   默认排序：逾期 > 今日待跟 > 意向明确 > 其他；逾期高亮 + 等级标签
   行内：快速跟进弹窗 / 拨号 / 复制 / 详情
        ↓
customer-detail.html（客户详情）
   转化信息 + 客户信息 + 结构化跟进时间轴 + 订单状态时间轴(可打开原因)
        ↓
customer-create.html（客户报备）
   单条报备（快速：姓名+手机+年级）/ 批量粘贴报备 → 成功后跳详情(first=1 高亮首次跟进)
```

## 三、数据模型变化（均为追加/复用，无破坏性迁移）

1. `db.leadFollowUps[]` 追加结构化字段（旧记录缺省为空，向后兼容）：
   `level`（高/中/低）、`concerns[]`（价格/时间/效果/竞品/家长态度/孩子意愿/其他）、`decisionMaker`（父母/孩子本人/双方/其他）、`budget`、`nextAction`（电话/微信/面谈/试听/发送方案）。
2. `db.leads[]`：沿用 `level`（跟进可选同步）；新增只写字段 `nextAction`。
3. `db.orders[]`：**复用** `cancelReason` 作为驳回/取消原因，代理端只读展示；不新增表、不改订单状态枚举。
4. 订单状态时间轴：**派生**（`orderLogs`/`payments`），不落库。

## 四、新增 / 修改的 Store 接口

| 接口 | 类型 | 说明 |
|---|---|---|
| `addLeadFollowUp(leadId, input)` | 修改 | 新增可选 `level/concerns/decisionMaker/budget/nextAction`；校验枚举；写入跟进记录并同步线索 `level/nextAction`；状态只能向前、必有跟进等原有规则不变 |
| `agentLeadView(leadId)` | 修改 | `orders[]` 增加 `timeline`（派生节点）与 `rejectReason`（取消/驳回原因） |
| `orderView(id)` | 修改 | 增加 `timeline` 与 `rejectReason`（管理端/兼容用） |
| `agentWorkbench(agentId)` | 新增 | 返回四入口计数与列表：`counts{todayFollow,overdue,intentNoOrder,pendingPayment}`、`todayFollow/overdue/intentNoOrder/pendingPayment` |
| `agentOrderTimeline(orderId)` | 新增 | 代理只读订单时间轴 + 驳回原因（不含收款流水明细） |
| `LEAD_CONCERNS / LEAD_DECISION_MAKERS / LEAD_NEXT_ACTIONS` | 新增导出 | 结构化字段枚举，集中维护 |

权限：`addLeadFollowUp` 走 `assertCan('lead.follow')` + `assertLeadAccess`；`agentLeadView/agentOrderTimeline` 走 `assertLeadAccess/assertOrderAccess`，代理只能读自身客户/订单。

## 七、已知问题与未验证事项

1. **页面交互未浏览器实跑**（🔧）：四页仅语法/接线静态校验；建议上线前做一轮点击验收（复制/拨号在真实浏览器、移动端）。
2. **「待确认收款」入口简化**（⚠️）：工作台该卡链接到 `my-customers.html?stage=payment`，当前在客户列表侧映射为「有订单」筛选，**未做订单级待收款列表**。如需精确到 ORDER.REVIEWED 订单清单，应新增订单视角或独立页。
3. **「待提交订单」口径**（⚠️）：定义为「意向明确且无订单」的客户（`intentNoOrder`），而非订单记录。
4. **取消 vs 驳回**（⚠️）：复用 `order.cancelReason` 展示原因；`ORDER` 无独立「已驳回」状态，若产品要求独立驳回态需扩展枚举（影响管理端审核与统计）。
5. **结构化字段枚举取值**（⚠️）：`concerns/budget/decisionMaker/nextAction` 默认值来自本规格建议，最终应以业务/字典维护为准（目前已集中为常量，便于替换为字典）。
6. **P1/P2 未做**（⚠️）：转化漏斗视图、试听节点、智能续费、佣金增强、公海/转介绍/模板库/完整结算均未在本轮实现。

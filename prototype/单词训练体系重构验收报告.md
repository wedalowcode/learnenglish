## 四、新旧业务流程对照

| 环节 | 旧流程 | 新流程 |
|---|---|---|
| 训练任务 | 选词库→逐词初筛→生成队列 | 内容确认清单（含学员掌握/到期提示）→ 去重初筛 → 生成队列 |
| 强化训练 | 分组逐词（`trainJudge`/旧卡片） | 列表工作台：每词三步展示 + 发音 + 标记需要强化（只记过程不判掌握） |
| 复习检测 | 认识/暂不确定/不认识 → 落 wordState | 统一 mastery 三态（掌握/待加强/未掌握）语义呈现，提交前可改 |
| 完成/提交 | `completeTask` 落 joins（莱特纳/21天/绿盒） | `completeTask` 幂等生成**训练报告 + 统一复习计划**，兼容 joins |
| 训练报告 | 无（仅课程级报告） | 会话级报告（掌握率/逐词明细/重点单词/评价） |
| 复习计划 | 两套独立体系（leitner/plan21）各自管状态 | 统一 `reviewPlans` 管「当前状态+下次到期」；莱特纳/21天作为策略落点（`planRef`） |
| 复习记录 | `leitnerRecords` + `plan21Records` 两套 | 统一 `reviewRecords`（追加不覆盖）+ 历史弱关联 |
| 家长端 | 课程报告 + 复习单词三视图 | 追加只读「训练报告 + 复习计划」 |

## 五、数据模型变化说明

### 新增集合（附加式默认，`normalizeDb` 补空数组，不删旧字段）

```js
db.trainingReports /* 训练会话级报告；task.reportId 回指，一任务最多一份 */
db.reviewPlans    /* 统一复习计划；(studentId,wordId) 同刻仅一条有效，历史版本 status=removed 归档 */
db.reviewRecords  /* 统一复习记录；追加不覆盖 */
db.config.reviewStrategy /* 可配置间隔策略，非散落硬编码 */
```

- `TrainingReport`：`id/taskId/studentId/teacherId/sessionDate/sourceWordbookIds/trainedCount/masteredCount/needsPracticeCount/notMasteredCount/masteredRate/words[]/teacherNote/createdAt`；`words[]` 每词含 `wordId/en/ph/mean/sourceBookNames/finalResult/mastery/masteryLabel/enteredReview/teacherNote`。
- `ReviewPlan`：`id/studentId/wordId/sourceTrainingSessionId/sourceTaskId/status(pending|in_progress|removed)/strategy/currentStage/nextReviewAt/lastReviewAt/mastery/createdAt/updatedAt/planRef`。
- `ReviewRecord`：`id/studentId/wordId/planId/sourceTaskId/reviewedAt/method/result/mastery/teacherId/nextReviewAt/note`。

### 既有结构增量（兼容，非破坏）
- `trainTask` 新增只读回指字段：`reportId`、`reviewPlanBuilt`（幂等判定）。
- `trainDisplays.displayStep` 记录新增可选 `needsReinforce`（标记需要强化，不影响掌握判断）；`displayStat().words[]` 透出该字段。
- 检测结果语义：底层仍存 `yes/mid/no`，新增映射 `mapResult` → `mastered/needs_practice/not_mastered`；**不重写历史值**。

- 角色守卫 `assertTeachingAccess()` 注入：`completeTask / generateTrainingReport / createReviewPlansFromTraining / recordReview / markTrainReinforce` —— 拦截代理/家长直调，教师另经 `assertMyTask` 归属校验，admin/staff/ops 保留管理能力。

## 七、历史数据兼容方案

- 新增集合全部为「附加式空默认」，`normalizeDb` 在加载时补空数组，不改动既有集合与字段。
- 不 bump 存储 key / 版本号导致迁移重置；历史莱特纳盒、21 天计划与记录、课程报告、旧训练任务（含 `results`）原样保留。
- 检测三态只做语义映射、不重写 `yes/mid/no` 历史值。
- 复习计划版本化：旧有效计划归档为 `status='removed'` + `supersededBy` 指向新版本，历史计划/记录不删除。
- 场景七测试（✅ `r9-closure-p4.js`）验证：历史莱特纳/21天只增不减、原课程报告数量不变、原 21 天计划仍可读。

## 十、未完成事项与已知风险

⚠️ **页面浏览器交互未实跑**：训练工作台、训练报告页、家长报告卡均仅静态检查与数据层验证，需在浏览器逐项手工/自动化验收（数据层所依赖的 Store 语义已由上述测试覆盖）。

⚠️ **部分覆盖**：
- `word-training-setup` 的「训练内容确认清单」未单独实现移除/调序 UI（去重与掌握/到期提示已在初筛清单体现）。
- 训练工作台未内置三种模式切换与组内上下翻页（列表一次展示整组，组间 `setTrainGroup` 已支持；模式沿用任务级设置）。

⚠️ **策略深度待业务确认**：统一复习计划与莱特纳/21天为「统一计划 + `planRef` 弱关联」；复习计划调整（`recordReview`）更新的是统一计划的 `nextReviewAt`，不会自动改写莱特纳盒子的 `box/graduated` 进度。若要求复习后反向同步旧体系状态，需额外业务确认并做增量同步，而非强推。

✅ 已知安全：`completeTask` 仍不扣课时；未触碰课时扣减与课程级报告；莱特纳/21天正式状态未被统一计划直接改写。

# 代理端客户详情页（customer-detail.html）· 详细信息架构 + 字段清单 + 交互说明

- 适用页面：`prototype/agent/customer-detail.html`
- 定位：代理日常「看客户、推状态、提交订单、看进展」的核心工作页；承载 P0#3（结构化跟进）与 P0#5（订单进度透明），并为 P1#6（转化视图）打底。
- 目标：一眼看清转化路径与下一步动作；跟进可沉淀可分析；提交订单后进度透明、不"失联"。
- 现有基础：`agentLeadView(leadId)` 已提供 `lead/followUps/orders/student/renewals/feedbacks/commission`；`addLeadFollowUp`、`markLeadIntent`、`submitEnrollmentOrder`、`submitRenewalOrder` 已存在；`orderView` 提供 `payments/logs`。

---

## 一、信息架构（三栏 + 顶部转化漏斗条）

```
┌─ 顶部：面包屑 + 客户名/状态/手机/孩子/年级/意向 + 主操作（记录跟进 / 转为意向 / 提交订单）─┐
├─ 转化漏斗条（横向节点）：报备 → 待联系 → 跟进中 → 意向明确 → 已成交/已关闭 ─────────────┤
│   当前节点高亮；已完成节点打勾；右侧显示「下一步建议动作」                                  │
├───────────────┬──────────────────────────────────┬───────────────────────────────┤
│ 左：客户信息    │ 中：跟进时间轴（结构化记录）        │ 右：学员与课时 / 学习反馈 / 续费机会 │
│  + 归属追溯     │  + 新增跟进（结构化工单）            │  / 成交订单状态时间轴 / 快捷操作    │
└───────────────┴──────────────────────────────────┴───────────────────────────────┘
```

- 与现状差异：现状为「客户信息 + 归属追溯 + 跟进时间轴 + 成交订单」两栏；本规格将其重组为 **顶部漏斗 + 三栏**，并新增「订单状态时间轴」「结构化跟进」两块。

## 二、页面区块与字段清单

### A. 顶部转化漏斗条（P1#6 基础）
| 节点 | 映射线索状态 | 展示 |
|---|---|---|
| 报备 | `NEW` | 已完成/当前高亮 |
| 待联系 | `TO_CONTACT` | |
| 跟进中 | `FOLLOWING` | |
| 意向明确 | `INTENT` | |
| 已成交 | `DEAL` | 终态 |
| 已关闭 | `INVALID / CLOSED` | 旁支终态（灰） |

- **下一步建议动作**：由当前状态派生（`LEAD_NEXT[status]`），如：跟进中→「转为意向」；意向明确→「提交报名订单」；已成交→「查看订单/发起续费」。
- 点击节点：仅展示该节点信息（不改状态）；状态流转仍走「记录跟进 / 转为意向 / 提交订单」按钮，且**只能向前**（服务端 `LEAD_NEXT` 校验）。

### B. 左栏 · 客户信息（沿用+补充）
字段：家长姓名、联系电话、学生姓名、学生年级、意向教材、意向课程、来源渠道、**意向等级（高/中/低）**、下次跟进时间、备注。
> 数据源：`agentLeadView().lead`（现有字段：`name/phone/kidName/grade/book/channel/status/level/intent/nextFollowAt/lastFollowAt`）。备注取自 lead 备注（`createLead.remark`）。

### C. 左栏 · 归属追溯（保持只读，微调）
字段：代理归属、维护归属、成交归属。文案继续说明「代理不可修改归属，冲突由管理员后台确认」。

### D. 中栏 · 跟进时间轴（结构化升级，P0#3 核心）
每条跟进记录展示（升级后）：
| 字段 | 说明 | 现状 |
|---|---|---|
| 跟进方式 `type` | 电话/微信/面谈/试听/其他（字典 `follow_type`） | ✅ 已有 |
| 沟通内容 `content` | 必填自由文本 | ✅ 已有 |
| 结果 `result` | 可空（如"已约试听"） | ✅ 已有 |
| 下次跟进 `nextAt` | 日期 | ✅ 已有 |
| **意向等级 `level`** | 高/中/低，记录当次评估（可选，写入后同步线索当前等级） | ❌ 新增字段 |
| **主要顾虑 `concerns[]`** | 多选：价格/时间/效果/竞品/家长态度/孩子意愿/其他 | ❌ 新增字段 |
| **决策人 `decisionMaker`** | 父母/孩子本人/双方/其他 | ❌ 新增字段 |
| **预算区间 `budget`** | 可选，如 <1万/1-2万/2万+ | ❌ 新增字段 |
| **下次动作 `nextAction`** | 电话/微信/面谈/试听/发送方案 | ❌ 新增字段 |
| 记录时间/记录人 | at / by | ✅ 已有 |

**跟进弹窗改造**（`#followModal`）：
```
跟进方式 [电话▾]   下次跟进 [日期]
意向等级 [高▾]     决策人 [父母▾]
主要顾虑 [价格][时间][效果][竞品][家长态度][孩子意愿]  ← 多选 chips
预算区间 [可选▾]   下次动作 [电话▾]
沟通内容 [必填 自由文本]
推进状态 [保持/允许的下一步▾]   ← 只能向前，不变
[取消] [保存跟进]
```
- 沟通内容仍**必填**；结构化字段除沟通内容外均为可选（降低录入成本）。
- 保存后：记录追加（不覆盖），`nextFollowAt` 更新；若选了意向等级且更高，同步 `lead.level`；`nextAction` 落在该条跟进上，供工作台「下次动作」提示。

### E. 中栏 · 成交订单状态时间轴（P0#5 核心）
每笔订单卡片展示：
| 节点 | 映射 `ORDER` 状态 | 说明 |
|---|---|---|
| 已提交 | 订单创建（`createdAt`） | 代理提交报名订单 |
| 待审核 | `PENDING 待审核` | 等教务/管理员审核 |
| 待收款 | `REVIEWED 待收款` | 审核通过，等收款 |
| 已入账 | `CREDITED 已入账` | 收款确认，学员建档、课时入账 |
| 已退款/已取消 | `REFUNDED / CANCELLED` | 旁支（灰/红） |

- 时间轴节点状态从 `orderLogsOf(id)` + `payments` 派生（`orderView(id).logs/payments`）。
- **驳回原因可见**：管理员驳回/取消时写入原因，详情页展示红条「驳回/取消原因：xxx」。
  - 现状：`ORDER` 无独立「已驳回」态；驳回落在 `CANCELLED` 或日志。**新增字段** `order.rejectReason`（管理员审核不通过/取消时写入，`reviewOrder/cancelOrder` 透传），并在 `orderView` 暴露，代理端只读展示。
- 订单卡片字段：订单号、套餐、课时、金额、已支付、状态、下单时间、入账时间、时间轴、驳回原因。

### F. 右栏 · 学员与课时（沿用）
字段：学员、当前教师、剩余课时（<5 红色）、状态。未成交时提示"课时只来自订单收款入账"。

### G. 右栏 · 学习反馈（沿用）
教师已发布反馈（`agentFeedbacksForStudent`），只读。

### H. 右栏 · 续费机会（沿用 + P1#8 预留）
续费机会列表 + 「发起续费订单」按钮（`submitRenewalOrder`）。

### I. 右栏 · 快捷操作
- 复制手机号 / 一键拨号（`tel:`）
- 记录跟进
- 提交报名订单（意向明确时）
- 发起续费（有续费机会时）

## 三、数据模型变化

1. `db.leadFollowUps[]` 追加结构化字段（向后兼容，旧记录缺省为空）：
```js
{ id, leadId, type, content, result, nextAt, by, byId, at,
  level:'',              // 高/中/低（可选）
  concerns:[],           // 多选：价格/时间/效果/竞品/家长态度/孩子意愿/其他
  decisionMaker:'',      // 父母/孩子本人/双方/其他
  budget:'',             // 预算区间（可选）
  nextAction:'' }        // 下次动作
```
2. `db.leads[]`：`level` 复用（已在 `markLeadIntent`/跟进可选同步）；**不新增冗余状态**，状态机保持 `LEAD` + `LEAD_NEXT` 只进不退。
3. `db.orders[]`：新增 `rejectReason`（管理员驳回/取消原因，可空，代理只读）。
4. 订单时间轴：不新增表，由现有 `orderLogs` + `payments` 派生（读取接口见下）。

## 四、Store 接口变化

| 接口 | 变化 |
|---|---|
| `addLeadFollowUp(leadId, input)` | 扩展入参 `level/concerns/decisionMaker/budget/nextAction`；校验：`concerns` 属固定枚举、`level ∈ LEAD_LEVELS`；写入 `f` 记录；若 `level` 且更高则同步 `lead.level`。状态流转与"必有跟进"规则不变。 |
| `agentLeadView(leadId)` | `followUps` 透出新结构化字段；`orders` 每笔附 `timeline`（派生节点）与 `rejectReason`。 |
| `orderView(id)` | 增加派生 `timeline`（已提交/待审核/待收款/已入账/退款取消 + at）与 `rejectReason`（代理可读的只读项；`payments/logs` 仍不外泄给代理的完整流水，见权限）。 |
| 新增 `agentOrderTimeline(orderId)`（可选） | 仅返回代理可见的节点与原因，不含内部财务明细。 |
| `reviewOrder / cancelOrder` | 写入/透传 `order.rejectReason`（管理员侧，代理不可调用）。 |

权限：均为 Store 业务入口校验（`assertLeadAccess` / `assertOrderAccess`），代理仅能读自己客户与其订单；`addLeadFollowUp` 走 `assertCan('lead.follow')` + `assertLeadAccess`。

## 五、交互说明（关键流程）

1. **记录跟进**：点「+ 记录跟进」→ 弹窗 → 填自由文本（必填）+ 结构化选项（可选）→ 保存 → 时间轴顶部插入新记录，`lastFollowAt/nextFollowAt` 更新，工作台待办联动。
2. **推进状态**：`followModal` 的「推进状态」仅列 `LEAD_NEXT[current]`；终态（已成交/无效/关闭）不显示记录入口；非法跳转由 Store 抛 `STATUS_TRANSITION_INVALID`。
3. **转为意向**：`markLeadIntent`（需至少一条跟进；现有规则不变）→ 漏斗更新。
4. **提交订单**：意向明确才出现按钮 → 选套餐 → `submitEnrollmentOrder` → 订单进入订单时间轴「待审核」。
5. **订单进度**：订单卡片时间轴节点按 `ORDER` 状态高亮；审核不通过/取消显示红色原因条。
6. **快捷操作**：复制手机号（`navigator.clipboard`，失败回退 `toast 手动复制`）、拨号（`tel:`）、发起续费。
7. **空状态**：无客户 → 引导报备；无跟进 → 提示"至少一条跟进后才能转为意向"（沿用）；无订单 → 提示未成交。

## 六、验收标准（本页）

- [ ] 转化漏斗 6 节点正确映射 `LEAD` 状态，当前高亮、已完成打勾、下一步动作正确。
- [ ] 跟进弹窗可保存结构化字段；时间轴回显 level/concerns/decisionMaker/budget/nextAction；旧记录空值不报错。
- [ ] 沟通内容仍必填；状态只能向前；终态不可再跟进。
- [ ] 订单时间轴按 `PENDING→REVIEWED→CREDITED` 正确推进；退款/取消分支显示；驳回原因可见。
- [ ] 代理不可修改归属、不可见其他代理客户/订单、不可见收款流水明细（只读节点与原因）。
- [ ] 刷新/直连 `?id=` 可恢复；无效/非本人 id 被 Store 拦截并显示提示。
- [ ] 数据层测试：`addLeadFollowUp` 结构化字段保存与回读、时间轴派生、驳回原因、`assertLeadAccess` 越权拦截（需实际运行）。

## 八、风险与待确认

1. **结构化字段取值**：`concerns` 枚举、`budget` 区间、`decisionMaker` 取值需与业务确认（本规格给出默认建议，最终以字典维护为准，避免散落硬编码）。
2. **取消 vs 驳回**：现 `ORDER` 无独立「已驳回」，本规格倾向「审核不通过」复用 `CANCELLED` + `rejectReason` 展示；若产品要求独立「已驳回」态，需扩展 `ORDER` 枚举（影响 admin 审核与统计，需评估）。
3. **收款流水边界**：代理只展示"待收款/已入账"节点与原因，不展示支付流水明细（与现有 `policy.canSeePaymentDetail=false` 一致）。

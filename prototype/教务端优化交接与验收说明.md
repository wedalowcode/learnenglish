## 二、信息架构

```
教务工作台 dashboard
  ├─ 教务今日待办：待排课需求 / 待补会议 / 待审核 / 待收款 / 异常课 / 未回复咨询 / 超时报告（点数字直达）
  ├─ 待处理事项：真实待办 + 「去排课/去补充/去审核/去收款/去处理/去回复/去跟进」按钮
  └─ 关键数字下钻：新增/在读学员→学员列表；课程完成→课程记录；课时消耗→课时流水；订单/收款→订单管理
        ↓
排课 schedule-calendar：选学员→带出教师；选教师+日期→当日已有课提示；待补会议批量补充
        ↓
订单 order-list：待审核/待收款快捷 Tab；收款成功→入账 X 课时→查看课时账户
课时 hour-account：余额不足/即将到期标签 + 续费入口；?student= 直达
        ↓
学员 student-list：未完成任务/近7天无上课筛选 + 发起续费；student-detail：教务备注 Tab
        ↓
课程 course-list：异常课程统一处理台（备注）；线索 lead-list：归属待审核；lead-detail：转化后引导
```

---

## 三、数据模型变化（附加式，无新集合）

1. `student.eduNote`：教务内部备注（仅 admin/staff/ops 可写；家长/代理/教师端不展示）。
2. `course.workNote`：异常课程处理备注（教务处理留痕）。
3. 未新增集合；未删除/迁移任何历史数据。

## 四、新增 Store 接口（均已导出，角色校验 admin/staff/ops）

| 接口 | 说明 |
|---|---|
| `eduWorkbench()` | 教务待办聚合：`counts` + `lists` + `orderStat` |
| `coursesMissingMeeting()` | 待补会议课程列表（待上/授课中且无链接） |
| `batchFillMeeting({courseIds, meetingUrl, reason})` | 批量补充会议链接（校验 http(s)，仅待上/授课中，审计） |
| `abnormalCourses()` | 异常课程（未上课/已取消/扣课异常 + 原因 + workNote） |
| `courseWorkNote(id, note)` | 异常课程处理备注（审计） |
| `orderQuickStat()` | 待审核/待收款/已入账数量与金额 |
| `overdueReports(days)` | 完成后超 N 天未发布的报告 |
| `unrepliedInquiries()` | 待处理/处理中的家长咨询 |
| `studentsWithOpenTrainTask()` | 有未完成训练任务的学员 |
| `inactiveStudents(days)` | 近 N 天无完成课程的学员 |
| `setStudentEduNote(id, note)` | 教务备注（审计） |

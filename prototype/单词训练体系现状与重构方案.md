# 单词训练体系现状与重构方案

LearnEnglish 一对一英语教学闭环 · 现状分析与重构设计

- 版本：v1.0（第一阶段交付，仅供评审确认，确认后再按阶段实施）
- 范围：单词训练任务 / 训练过程 / 复习检测 / 训练报告 / 统一复习计划 / 家校衔接 / 数据模型收口
- 结论先行：当前体系已具备「单词卡片式训练闭环」，但**训练过程掌握结果与课程级报告、两套复习体系互不打通**，缺少「训练会话级报告」和「统一复习计划」，需要新增数据结构，而非推倒重建。

## 二、当前已实现的能力（现状地图）

### 1. 训练任务对象（`db.trainTasks`）
一个任务对象承载全流程状态机，字段（来自 `createTrainTask`）：

```
id, studentId, teacherId, courseId(可挂课程), wordbookIds[], wordbookName,
targetCount, groupSize, displayFlow,
status: PENDING/ACTIVE/INTERRUPTED/DONE/CANCELLED,
phase: 预筛选 → 强化训练 → 最后复习 → 已提交,
wordIds[](去重候选池), candidateWordIds[], knownWordIds[], queueWordIds[], remainWordIds[],
prescreen(wordId→{known,at,by,wordbookId}),
results(wordId→旧版掌握判断,仅非 displayFlow), finalResults(wordId→{result,at,correctedFrom,corrections}),
groupIndex, wordIndex, finalIndex, mode, pausedAt, finishedAt,
joins{ leitner[], plan21[], planIds[], green[] }, prescreenStats{}
```

### 2. 训练过程记录
- `prescreens[]`：初筛判断（`known`/`wordbookId`/`at`/`teacherId`/`correction/correctionFrom/Note`）。
- `trainDetails[]`：旧版逐词判断记录（`result`, `round`, `correction...`）。
- `trainDisplays[]`（第九轮起，displayFlow）：每组每词独立展示步进 `displayStep 0→1→2→3`，`cycleCompleted`、`taps`，**不写结果/不产生掌握判断**。
- `studentWordStates`（`wordState`）：`state ∈ {未训练,初筛认识,待强化训练,待最后复习,本次通过,暂不确定,待复习…}`，随训练推进被 `setWordState` 改动。

### 3. 复习检测（最后复习）
- `finalJudge` 列表式三种结果 `yes/mid/no`（页面映射为 认识/暂不确定/不认识），提交前可重判（记录 `correctedFrom`）。
- `completeTask`：按 `finalResults` 落 `本次通过 / 待复习 / 暂不确定` 到 `wordState`，并按 `joins` 勾选写入莱特纳/21 天/绿盒。
- **幂等**：`status!==DONE` 才可提交，重复提交返回 `ok:false`。

### 4. 两套复习体系（互不关联）
- 莱特纳盒：`db.leitnerStates`（`boy→box ∈ {red,yellow*,green,graduated}` + `dueAt/lastReviewAt/lastResult/manualToday/source/sourceTaskId/by`）；`leitnerRecords[]` 历史复习记录；间隔由 `db.leitnerConfig`（红/黄盒 intervalDays）决定。
- 21 天记忆法：`db.plans21`（`wordIds,startDate,status`）+ `plans21Tasks`（按 `plan21Strategy.nodeDays` 生成逐日任务 `date→wordIds`）+ `plans21Records`（`planId,wordId,result,at`）。间隔由 `db.config.plan21Strategy` 决定。
- 学员级当前掌握兜底：`studentWordStates`（`wordState`）。
- 家长视图已按两体系**读侧合并**（`buildParentReviewRows` 按 wordId 去重，标注所属体系），今日到期/全部/已通过三视图。

### 5. 报告与家校衔接
- 训练完成不生成「训练会话级报告」。
- 报告体系是**课程级**：`db.reports`（字段 `performance/weak/next/homeworkAdvice`）由课程完成后教师整理，`publishReport`/`syncFeedbackFromReport` 生成家长可见的「学习反馈」。
- 家长端 `parentReports/parentReportDetail` 只读课程级报告；`parentReviewWords` 读复习单词。
- 权限：训练操作入口已有 `assertMyTask`（此前补全），家长端 `assertParentChild`、审计 `assertCan('audit.view')` 均已在 Store 层。

## 四、需要修改的能力

1. **训练任务语义**：新增 `draft / in_progress / pending_assessment / completed / cancelled` 状态语义映射。现状 `status+phase` 两维度表达，易混淆。建议保留 `status`（生命周期）与 `phase`（阶段），隐式对齐新状态：`draft≈预筛选中(PENDING)`、`in_progress≈强化训练(ACTIVE)`、`pending_assessment≈最后复习(FINAL)`、`completed≈已提交(DONE)`、`cancelled≈已取消(CANCELLED)`。**不新增字段**，只做语义收敛 + 页面文案，避免破坏历史。
2. **训练内容确认**：在 `word-training-setup` 增加「已选单词清单确认」（英文/音标/中文/来源词库/学员历史状态/是否到期复习），教师可增删调序。现状仅按词库加入 + 初筛，需在创建前提供确认。
3. **训练过程工作台**：把 `word-training.html` 强化阶段从「按组 5 词列表展示」演进为「教师工作台」：支持发音播放/再次播放、显示/隐藏中文、上一下一、标记需要强化、暂停。三种模式（英看中/中忆英/听音识词）作为教师可选模式（复用现有 `wordbook` 词义/音标/发音数据）。
4. **完成训练**：全部单词完成训练后不能直接 DONE，必须进入 `pending_assessment`（现状已通过 `toFinalStage` 强制进入最后复习，符合；需把「进入检测」显式与「全部掌握」解耦——现状 `trainDisplayTap` 只记展示不记掌握，已满足）。
5. **复习检测结果语义**：现状 `yes/mid/no` → 新方案 `mastered/needs_practice/not_mastered`。需做语义映射（`mid→needs_practice`、`no→not_mastered`、`yes→mastered`），写入检测结果与后续复习计划，同时**保留历史 `yes/mid/no` 记录**做兼容。
6. **完成检测动作**：现状 `completeTask` 一次性完成「落状态 + 可勾选加入两套体系」。需改为「**生成训练报告 + 创建统一复习计划**」两个独立且幂等的副产物（见新增结构），并保留「加入莱特纳/21 天」作为复习策略的落点。

## 五、需要新增的数据结构

> 原则：优先复用现有对象；以下为「职责对象」，不强制全部新增独立表。多数可挂在 `db.trainTasks` 现有字段 + 少量新集合。

### 1. TrainingSession 级报告（新增，核心缺口）
现状没有「训练会话级报告」。建议新增 `db.trainingReports`：

```
{
  id, taskId(一对一, 1 task → 最多 1 报告), studentId, teacherId,
  sessionDate, durationMin(可选), sourceWordbookIds[],
  trainedCount, masteredCount, needsPracticeCount, notMasteredCount, masteredRate,
  resultSummary: { mastered:[], needs_practice:[], not_mastered:[] },  // 或明细行
  teacherNote: { overall, performance, problems, nextAdvice },
  createdAt, updatedAt, publishedAt
}
```
明细（每词）：`db.trainingReportWords`（或内嵌数组）——`wordId, en, ph, mean, sourceBookIds, finalResult, teacherNote, enteredReview`。
只由 `completeTask` 幂等生成一次（`task.reportId` 回指，重复提交不重复建）。

### 2. 统一复习计划（新增，关键架构对象）
现有两套体系数据是「状态两处 + 记录两处」，无法回答「一个学员的某个基础单词当前有效的复习计划与下次到期」。建议新增 `db.reviewPlans`：

```
{
  id, studentId, wordId, sourceTrainingSessionId, sourceTaskId,
  status: pending / in_progress / removed / graduated,
  strategy: 'leitner' | 'plan21' | 'unified',   // 该单词当前由哪套策略负责到期
  currentStage, intervalDays, nextReviewAt, lastReviewAt,
  planRef: { type:'leitner', key: leitnerStateId } 或 { type:'21', planId, taskDay },   // 与旧体系行关联映射
  createdAt, updatedAt
}
```
- 唯一性约束：**同一个 `(studentId, wordId)` 同一时刻只允许一条 `status∈(pending,in_progress)` 的有效计划**。当训练检测完需要入复习计划时：若已存在有效计划 → 决定「覆盖更新计划」还是「建立新版本」；建议建立**计划版本**（`version` 或新行 + 旧行置 `removed`），绝不删除历史。
- 复习间隔一律走可配置策略（`db.config.reviewStrategy`），不散落硬编码天数。

### 3. 统一复习记录（新增）
现有 `leitnerRecords` 与 `plan21Records` 是两套。新增 `db.reviewRecords` 作为**统一复习事实日志**：

```
{ id, studentId, wordId, planId, sourceTaskId?, reviewedAt, method:'train'|'leitner'|'plan21'|'family',
  result: mastered|needs_practice|not_mastered, teacherId?, nextReviewAt?, note,
  weakRefs: [旧系统记录ID] /* 关联原始 leitner/plan21 记录，便于追溯不覆盖 */ }
```
复习记录**追加不覆盖**；同时把旧系统记录作为来源保留。

### 4. TrainingAction（按需，低优先）
训练行为（开始/完成时间、模式、播放次数、标记需要强化、教师备注）——现状 `trainDisplays` 已涵盖展示步进，**不必新增独立动作表**；缺「标记需要强化」「教师备注」可扩 `trainDisplays` 或 `trainTask.wordsMeta[wordId]`。**不作为必须新增项**，避免大量无意义埋点。

## 七、新老数据迁移方案

1. **只读历史、加新对象**：训练任务/初筛/展示/最后复习/莱特纳/21 天/课程报告**原样保留**；新增 `trainingReports / reviewPlans / reviewRecords` 三个集合，`normalizeDb` 补默认空数组，不改旧集合结构。
2. **回填策略（可选批次）**：为「已完成的训练任务」若 `joins.leitner/plan21` 有内容，可批量反查生成一条潜意识复习计划草稿；**不作为 v1 必须项**，先保证读侧兼容。
3. **`studentWordStates.state` 语义漂移**：现状 `待复习/暂不确定/本次通过` 等混合描述掌握；建议在 `wordState` 新增只读投影 `mastery: mastered|needs_practice|not_mastered|unknown`（由 `finalResults`/最近一次 `reviewRecords` 推导），**不重写 `state` 历史值**。
4. **迁移载体**：沿用 `loadLegacyV8` 的「按集合搬运 + 备份旧 key」模式；版本号随集合增加，`meta.migration` 记录 `carried/seeded/backupKey`。
5. **幂等防重复**：训练任务 `reportId` 回指、`planIdRef` 回指，任何副产物以「是否存在回指」判定，杜绝重复生成。

## 八、页面交互说明（目标态）

### 教师端
- `word-training-setup`：新增「训练内容确认」清单（当前掌握状态、是否到期复习、来源词库），支持移除/添加/调序/详情，确认后创建任务（draft）。

- 新增「训练报告」查看页（复用学生档案或独立页）；可查看逐词明细/重点单词（待加强+未掌握）/后续复习安排。

### 家长端
- `parent/report.html` 或新增区域：查看该学员的训练会话级报告（掌握统计/掌握率/逐词明细/待加强与未掌握/后续复习安排）。

### 权限执行纪律
- 训练、检测、报告、复习计划的所有写入口沿用 `assertMyTask`（教师归属）与 `assertCan`/`hasPermission`；家长读入口 `assertParentChild`；代理不可写教学结果。杜绝仅前端隐藏。

## 九、数据一致性规则（设计约束）

1. 训练任务仅能完成一次（`status` 防重）；重复提交检测返回幂等 `ok:false`。
2. 检测未全判断不可提交（`finalMissing` 校验，已存在）。
3. 每个任务最多一份 `trainingReports`（`task.reportId` 回指唯一）。
4. 复习计划：`(studentId, wordId)` 同一时刻仅一条有效；入复习时若有旧计划则归档为新版本，历史计划/记录不删。
5. 复习记录追加不覆盖，保留原始判断/修正前后/操作人/原因。
6. 教师转移：任务归属以创建时 `teacherId` 绑定，历史任务不自动转新教师（沿用 `assertMyTask`）。
7. 词库授权被取消 / 词库被删除：历史训练与报告通过「词库快照/来源词库 id + 训练时单词词义快照」保持可读（需在训练确认时对 `TrainingWord` 存 unstable sources 或词义副本；此前 `prescreen` 已存 `wordbookId`，`word` 需在 `wordPanorama` 层做快照兼容）。
8. 多词库重复单词：训练始终按基础 `Word.id` 去重（已有）。

## 十一、必须通过的端到端场景与验收口径

| 场景 | 验收断言（数据层，非仅页面） |
|---|---|
| 一·正常训练 | 检测结果 → `trainingReports` 统计=三态计数；`masteredRate=已掌握÷总数`；报告与复习计划数量一致；待加强+未掌握全部进复习计划，掌握的不进 |
| 二·中断恢复 | 已完成单词/进度持久化保留，恢复后不重复计算检测结果 |
| 三·多词库重复词 | 训练清单中同一基础 Word 只出现一次，`sourceBooks` 保留多来源 |
| 四·复习计划正确性 | 掌握/待加强/未掌握→不同间隔策略；复习后产生 `reviewRecords` 且 `nextReviewAt` 动态调整，计划状态更新 |
| 五·重复操作 | 重复提交检测/重复完成/重复生成报告/重复建计划均幂等（回指 + status 防重） |
| 六·权限 | 教师只能操作归属学员（`assertMyTask`）；家长只能看关联学员（`assertParentChild`）；代理不可写；Store 直调鉴权（审计 `assertCan`） |
| 七·历史兼容 | 历史训练/莱特纳/21 天/课程报告数据不变可读；新增集合不影响旧数据 |

验收测试需**真正运行**并区分「已运行通过 / 仅静态检查 / 仅测试代码未执行 / 未验证 / 已知问题」，不得以文件存在冒充通过。

## 十二、已知风险与待业务确认点

1. **语义映射**：`yes/mid/no → mastered/needs_practice/not_mastered` 的映射与产品口径（尤其 `mid`）需确认。
2. **两套体系如何成为「策略」**：莱特纳/21 天现有数据结构差异大，统一 `reviewPlans.strategy` 的细粒度（是否保留 `planRef` 弱关联）需评审。
3. **词义快照**：为「词库被删/词义改写后历史报告仍可读」，需确认在训练确认时对词义做快照的成本。
4. **复习计划与旧体系冲突**：同一词已有 21 天任务又在训练中判定未掌握，是「并入原计划」还是「新建计划版本」——方案默认「版本化」，需确认。
5. **不改课时**：本重构仅涉教学训练，不触碰课时扣减与课程报告版本，与课时逻辑完全解耦（已确认 `completeTask` 不扣课时）。

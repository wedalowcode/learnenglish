存储版本 v3
i
本轮不新增页面，只修数据完整性。所有业务校验都在 Store 层执行—— 页面按钮被绕过、脚本被直接调用、重复点击都不会产生脏数据。 任何 ok:true 都代表数据已真实写入并持久化。
修了什么
1 · 复习记录重复提交
21 天与莱特纳：单词必须属于当前任务 / 节点；同任务同词只能一条首次判断记录； 重复提交被拒绝并提示走「修正」。完成度按唯一 wordId 统计，修正不会虚增。
2 · 修正与首次判断分离
新增 plan21Correct / leitnerCorrect；训练侧 trainCorrect / finalCorrect 统一必填原因。修正追加新记录，保留原结果、新结果、时间、教师、原因。
3 · 莱特纳修正不重复推进盒子
修正以「本轮开始前的原盒子」为基准重算目标盒子，不在已推进的盒子上再推一次。
4 · 空复习计划
全部通过时不创建空 21 天计划、不生成空任务、不写 undefined； create21Plan 拒绝空清单并自动去重、过滤无效单词。
5 · 文章训练接入 Store
新增 articleTasks / articleTaskDetails；逐句播放、查看中文、跟读确认逐条落库； 刷新可继续，提前结束保留已有记录，不触碰单词掌握状态。
6 · 家长端复习词表
删除页面私有 WORDS 数组，改为按学员从 Store 派生，支持体系 / 词库筛选； 家庭复习勾选写入辅助表，不改变正式学习状态；打印内容与筛选结果一致。
7 · 课时冲正
校验原流水存在 / 类型可冲正 / 金额不超原始变动 / 禁止重复全额冲正； 新增方向相反流水、更新账户余额、原流水保留、记录原因与关联流水。

第三轮迭代 · 课程工作台与教学闭环 课程成为所有教学行为的上下文 · 状态五态统一 · 报告提交发布两道门
存储版本 v4
i
本轮把「功能闭环」升级为「课程闭环」。教师从课程工作台进入单词训练、莱特纳复习、21 天复习、文章训练， 所有判断记录都自动带上 courseId，不需要重复选学员； 课程结束由系统汇总成本节课教学记录，教师补评价、提交报告、发布后家长才可见。
这一轮解决的六个问题
1 · 课程工作台（唯一入口）
课程头（学员 · 第 N 课时 · 时间 · 状态）→ 四个教学入口（各带真实状态与动作）→ 本节课教学记录实时汇总 → 教师备注 → 保存并完成。从任一入口进去，courseId 一路透传，判断记录自动归属本节课。
2 · 状态只用五个词
任务型对象统一为 未开始 / 进行中 / 已完成 / 已中断 / 已取消； 废除 submitted、interrupted 这类布尔拼装。中断必须写原因，并显示「完成 8 / 20 · 剩余 12」。
3 · 状态与排期分开
21 天节点用 status 表达生命周期，用 dateState（今日 / 未到期 / 已逾期 / 休息 / 已完成）表达排期， 两个维度互不混写；模块内部阶段另用 phase（预筛选 / 强化训练 / 最后复习）。
4 · 先看现在，再看过去
单词学习档案顶部新增「当前学习全景」：当前状态、莱特纳盒位与阶段、21 天进度、最近一次训练， 下面才是完整时间轴。
5 · 教学结果，而不只是做过
文章逐句新增教师判定「掌握 / 待加强」+ 备注，课程结束汇总「总句数 / 确认掌握 / 待加强」直接进报告； 两套复习体系顶部说明「为什么今天要复习这些」。
6 · 未完成内容与可见性
课程结束时检测未完成任务，三选一：保留，下次继续（默认） / 结束本次任务 / 取消剩余内容（后两者必填说明）。 课程完成后报告为「编辑中」，须提交、再发布，家长才可见。
端到端验证路径（一节课走完）
① 进课堂
今日工作台 → 今日课程表「进入课堂」→ 课程工作台自动把课程状态改为授课中， 课程头显示学员 · 第 N 课时 · 状态，四个入口都带着 ?course=。
② 做教学
从「单词训练」入口进去建任务 → 预筛 → 强化训练判断几个词 → 回工作台， 「本节课教学记录」四格与明细表立刻出现数字，刷新不变。
③ 结束课程
点「保存并完成本节课」→ 弹窗列出未完成内容（例：单词训练 5 / 8）→ 选「保留」→ 确认 → 课程 已完成、扣 1 课时并生成流水、自动生成报告（编辑中）。
④ 写报告
跳到报告页：左栏是自动汇总，右栏是状态步骤条（未生成 → 编辑中 → 已提交 → 已发布）。 三段评价没填齐提交会被拒绝；提交后表单变只读，出现「发布给家长」。
⑤ 家长可见性
提交但未发布时，家长端只看到「老师正在整理本节课报告」；点发布后家长端才显示完整内容与逐句判定结果。
⑥ 中断与恢复
莱特纳复习点「提前结束」→ 必须填中断原因 → 卡片显示「已中断 · 完成 x / y · 原因」，可点「恢复本次复习」继续。

设计假设与待确认项PRD 未明确处，原型按下列假设实现，并显式标注
  • 1. 莱特纳算法参数（黄盒数量、间隔天数、答对/答错去向） — PRD 明确要求配置化、不写死。原型在「莱特纳复习」页提供「盒子配置」抽屉，展示为可配置项，未预设某套固定算法；复习执行页只记录结果并提示去向由配置决定。
  • 2. 21 天节点与每日上限 — PRD 列为待确认。原型时间轴展示 21 天节点与每日任务量，标注「按机构配置生成」，未固化具体节点规则。
  • 3. 两套复习体系是否默认同时加入 — 训练结果页提供两个互相独立的勾选项（默认均不勾选），并提示「是否默认同时加入由机构配置决定」。
  • 4. 佣金规则（比例 / 固定金额、确认时点、退款冲回、结算周期） — 列为待业务确认。代理详情与佣金页展示「规则待确认」状态标签，不做自动计算假设。
  • 5. 未付款订单是否可赊销加课时 — 原型按「不可」实现：订单状态为待付款时，课时账户不增加，并给出提示。
  • 6. 迟到 / 临时取消 / 缺课责任划分 — 待机构确认。课程状态含「未上课」，扣课状态独立展示，不自动扣课。
  • 7. 角色与权限 — 原型以三套菜单体现老板/教务、教师、代理，家长为移动端；权限点（如赠送课时、退款、冲正）在界面以「权限控制」标签标注，未实现完整 RBAC 配置矩阵。
  • 8. 腾讯会议链接 — 原型以「已生成 / 未生成」状态字段模拟，未接入真实 API。
数据口径对照对应 PRD 5.1 与 7.5
新增学员：按首次创建学员档案时间统计，不按首次上课时间。
在读学员：状态为在读且服务关系未关闭（暂停/关闭不计入）。
课程完成数：按实际上课并提交完成结果的课程记录统计。
课时消耗：按已确认扣课流水汇总，冲正不计入消耗。
订单金额：订单应收金额合计，与实收分开统计。
实际收款：按已登记收款记录统计，不得用订单金额替代。
可用余额：已入账 − 已扣除 + 已补入 − 已冲减，只能由流水驱动。
训练数量 ≠ 掌握数量：学习档案中两个指标分列并注明口径。

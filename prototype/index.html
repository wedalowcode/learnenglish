存储版本 v3
i
本轮不新增页面，只修数据完整性。所有业务校验都在 Store 层执行—— 页面按钮被绕过、脚本被直接调用、重复点击都不会产生脏数据。 任何 ok:true 都代表数据已真实写入并持久化。
修了什么
1 · 复习记录重复提交
21 天与莱特纳：单词必须属于当前任务 / 节点；同任务同词只能一条首次判断记录； 重复提交被拒绝并提示走「修正」。完成度按唯一 wordId 统计，修正不会虚增。
2 · 修正与首次判断分离
新增 plan21Correct / leitnerCorrect；训练侧 trainCorrect / finalCorrect 统一必填原因。修正追加新记录，保留原结果、新结果、时间、教师、原因。
3 · 莱特纳修正不重复推进盒子
修正以「本轮开始前的原盒子」为基准重算目标盒子，不在已推进的盒子上再推一次。
4 · 空复习计划
全部通过时不创建空 21 天计划、不生成空任务、不写 undefined； create21Plan 拒绝空清单并自动去重、过滤无效单词。
5 · 文章训练接入 Store
新增 articleTasks / articleTaskDetails；逐句播放、查看中文、跟读确认逐条落库； 刷新可继续，提前结束保留已有记录，不触碰单词掌握状态。
6 · 家长端复习词表
删除页面私有 WORDS 数组，改为按学员从 Store 派生，支持体系 / 词库筛选； 家庭复习勾选写入辅助表，不改变正式学习状态；打印内容与筛选结果一致。
7 · 课时冲正
校验原流水存在 / 类型可冲正 / 金额不超原始变动 / 禁止重复全额冲正； 新增方向相反流水、更新账户余额、原流水保留、记录原因与关联流水。

这一轮新增了什么
1 · 代理全生命周期
招募建档（待审核）→ 审核通过（启用）→ 停用 / 恢复；代理身份由会话提供， 页面不写死任何工号或姓名。
2 · 线索与跟进
线索状态：新线索 → 待联系 → 跟进中 → 意向明确 → 已成交 / 无效 / 已关闭， 只允许向前流转；每次跟进、状态变更、归属调整都写线索日志（只追加）。
3 · 报名订单与收款入账
待审核 → 待收款 → 已入账；收款金额必须与订单一致，部分收款不生成课时。 收款确认在同一事务中完成：写收款记录、创建课时账户、写购买/赠送流水、 重算学员余额、推进线索成交、关闭续费机会。
4 · 最小数据投影
代理只看自己负责的客户、订单与已发布学习反馈；家长只看自己孩子的订单状态、 课时汇总与已发布报告，不展示收款流水与他人信息。
5 · 续费与佣金边界
剩余课时低于阈值或套餐临期自动生成续费机会；续费仍走订单收款入账。 完整佣金结算、企微机器人、第三方支付接入本轮不做，只保留规则文本与预估接口、 状态字段与方式占位。

存储版本 v7
i
本轮把「发需求 → 教师接单 → 定人选 → 建关系 → 开词库」全链路纳入系统。 教师响应只表达意向（不改变学员当前教师）；教务确认只决定人选（不建师生关系）； 管理员分配才正式建立负责关系（复用既有师生关系机制，原子事务）； 词库授权只控制使用范围（不保存训练进度）。每个环节都记录责任人、时间、结果与业务关系， 不用一个简单的教师 ID 字段代替整条业务链。企微群暂时保留，本系统先管系统内闭环。
这一轮新增了什么
1 · 学员需求池（教务）
已有学员直接发需求，新学员先建档再发（不重复建档）；需求 10 项字段、7 种状态 （草稿 → 待接单 → 接单中 → 待教务确认 → 待管理员分配 → 已完成分配 / 已取消）， 编辑、撤回、取消必填原因，操作流水只追加。
2 · 教师接单中心
只显示面向可授课教师开放的需求；卡片展示年级 / 教材 / 方向 / 时间 / 特殊要求， 不暴露家长联系方式。「我可以带」与「暂不接单」（5 种原因）两条路径； 同一需求只有一条有效响应，确认前可撤回；暂停 / 已退出 / 待启用教师看不到也接不了。
3 · 教务确认人选
需求详情内响应列表 + 五项确认前检查（合作状态 / 账号 / 学员数量 / 年级教材匹配 / 时间）， 检查只是提示不是硬禁止，特殊情况允许确认但必须写说明； 确认后保存最终教师、确认人、时间、理由，未选中响应标记保留，可撤销重选，历史不删。
4 · 管理员正式分配
分配前六项检查；调既有 assignStudent / transferStudent： 同学员同时最多一名主教师，换教师 = 原关系结束 + 新关系创建， 已完成课程归属不变；关系上写入需求编号；分配与需求推进在同一事务，失败整体回滚。
5 · 词库申请与授权
词库资源、学员授权、教师实际使用三者分开：教师为自己负责的学员提交申请 （可一次多个，整体预校验）；管理员单条 / 批量审核、批量开通、驳回必填原因； 通过即创建 StudentWordbook 授权；同学员同词库不重复授权； 管理员可主动开通（记录操作人与原因）；停用不删记录、不删训练历史。
端到端验证路径（十个场景）
① 正常接单　教务发需求 → 教师响应 → 确认 → 分配 → 学员教师更新，关系带需求编号。
② 无人响应 / ③ 拒绝接单　需求停在接单中；拒绝必填原因并记录。
④ 撤回响应　确认前教师可撤回，撤回原因与时间入库。
⑤ 教师状态变化　暂停 / 退出教师不能接单、教务也不能确认。
⑥ 已有负责教师　分配走换教师：原关系结束、新关系创建、历史课程教师不变。
⑦ 正常词库申请　两个词库两条申请 → 审核通过两条授权 → 教师端立即可用。
⑧ 重复申请　提示已授权，不生成重复申请 / 授权。
⑨ 越权操作　教师查他人需求 / 为他人学员申请 / 教务直接分配 → 全部被 Store 拦截。
⑩ 异常与持久化　分配 / 批量审核失败整体回滚，不出现半条数据；刷新后状态仍在，操作人可追溯。

第五轮迭代 · 兼职教师全生命周期 合作状态与账号状态分离 · 师生关系独立成表 · 退出必须交接
存储版本 v6
i
本轮把教师从「员工记录」改成「资源池」。 机构教师全部兼职（大学生、在校研究生、其他兼职人员），流动频繁： 有人中途暂停、有人正式退出、退出后又回来。
所以教师档案要与登录账号分离（账号只解决能不能登录）， 教师与学员的负责关系要独立成表（不能只在学员表存一个 teacherName 然后覆盖）， 每次状态变更都要留合作流水，而历史课程永远保留当时的授课教师。
这一轮解决的六个问题
1 · 三套状态词表，互不推导
合作状态（待启用 / 可授课 / 暂停合作 / 已退出）、账号状态（未开通 / 正常 / 已禁用）、 课程状态（待上课 / 授课中 / 已完成 / 未上课 / 已取消）各管一件事： 暂停合作不等于课程取消，账号被禁用也不等于合作结束。
2 · 建档轻量，逐步完善
只填姓名 + 手机号即可建档，编号自动生成（T001…），初始状态「待启用」。 手机号同机构唯一；已退出教师再次录入会被拦下，只能走「恢复原档案」，同一自然人不产生第二份档案。
3 · 师生关系独立成表
teacherStudents 记录谁在什么时间负责谁、分配原因、结束原因； 换教师 = 原关系结束 + 新关系创建，历史关系永不删除。 学员表的 teacherName 只是派生缓存，由关系表实时重算。
4 · 暂停与恢复
暂停要填原因、开始日期、预计恢复；系统检查未来有效课程，逐节决定「保留待确认 / 改派 / 取消」； 当前学员关系保留但标记需教务关注，不因暂停而删除归属。恢复后关系不自动重建，由教务重新确认。
5 · 退出是一套交接流程
先列当前学员（含剩余课时、最近授课、是否有接替教师），再列未来课程与未完成记录； 每个学员必须「转交 / 解除」，每节课必须「改派 / 取消 / 保留待调整」，否则不允许确认退出； 整个退出在一个事务里完成，中途失败（含账号禁用失败）整体回滚。
6 · 历史永远不被覆盖
课程自带教师快照（ID + 编号 + 姓名）；已完成课程禁止改派；改派只发生在未来课程上， 并且写入改派记录（原教师 / 新教师 / 原因 / 操作人 / 时间）。
端到端验证路径（九个场景）
① 新教师加入　教师管理 → + 新增教师 → 填姓名与手机号 → 自动生成 T008，状态「待启用」；重复录入同一手机号被拦下。
② 教师启用　详情页开通账号 → 完善教学能力 → 启用 → 状态变「可授课」，排课与分配界面立即可选。
③ 负责学员　详情页「分配学员」→ 选学员 + 填原因 → 学员当前教师更新，刷新后仍在。
④ 暂停合作　填原因 → 处理未来课程 → 确认 → 从可分配池消失，历史记录仍可查。
⑤ 恢复合作　详情页「恢复合作」→ 账号重新启用 → 原学员关系不自动恢复。
⑥ 教师更换　学员列表「分配教师」或教师详情「更换教师」→ 原关系结束、新关系创建；张老师的历史学员里仍能看到该学员。
⑦ 正式退出　有 3 名学员 + 2 节未来课 → 退出向导逐项处理 → 确认退出 → 账号禁用、历史全部保留。
⑧ 重新加入　已退出教师用同一手机号再录入 → 提示恢复原档案 → 重新走启用流程，历史合作记录仍在。
⑨ 异常保护　有学员/未来课时不能退出；中途失败整体回滚； 历史课程教师不可批量覆盖；无权限角色调用写操作直接被 Store 拦截。

第四轮迭代 · 词库批量导入与资源入库 一份 Excel 一个词库 · 基础单词跨库复用 · 文件级原子入库
存储版本 v5
i
本轮把「资源入库」从单文件演示做成真实场景。 机构一次收到十几份 Excel，批量选中后浏览器本地真实解析（SheetJS，不上传服务器）， 每个文件生成一个词库，词库名称/分类/学段/版本/年级等可在入库前逐个修改； 同一个英文单词出现在不同词库里，只保留一条基础单词，多出来的只是词库关联。
这一轮解决的六个问题
1 · 真选择、真解析
多选 / 拖拽 / 追加 / 移除 / 清空；解析后按文件给出工作表、表头行、数据起始行。 封面页、说明页不会被当成数据；表头用同义词识别（单词 / 英文 / word / 词汇…）， 认不出就手动映射，不按位置猜列。
2 · 三段式词库模型
words 基础单词（按英文唯一）+ wordbooks 词库 + wordbookWords 关联。 排序、来源文件、原始行号都记在关联上：调整本词库顺序不影响其他词库， 从词库移除单词也不删除基础单词、不动学员学习状态。
3 · 三类重复分开计数
A 文件内重复 → 跳过重复行；B 目标词库已有 → 跳过重复关联； C 其他词库已有 → 复用基础单词，只新增关联。 三种数量在文件卡片和导入记录里分别统计，不混成一个「重复」。
4 · 文件级原子入库
先算完整写入计划，再一次性落库；中途任何异常整体回滚，不会出现「建了词库只写了一半单词」。 一个文件失败不影响同批其他文件已经成功的词库。
5 · 入库留痕与失败行
每次导入生成批次 + 文件级记录：解析行数、新增基础单词、新增关联、跳过、失败、失败原因。 缺必填 / 格式异常的行可下载成 CSV（带 BOM，Excel 直接打开），修正后重新导入。
6 · 词库可维护、可被训练使用
列表按名称 / 分类 / 学段 / 版本 / 状态筛选，可启停；详情按词库 ID 取本词库的关联单词， 支持搜索、筛缺音标/缺音频、调排序、编辑基础单词、移除关联、继续导入、查看导入历史。
端到端验证路径（五个场景）
① 一次选 3 个文件 → 3 个词库
资源中心 → 批量导入 → 选中 WOWEnglish-全季.xlsx、小学考纲词库.xlsx、 初中超前词汇.xlsx → 三张卡片各自显示解析行数与有效单词 → 全部入库 → 生成 3 个词库。
② 入库前改信息
在卡片「入库信息」里把名称改成「WOWEnglish 全季词库」、分类改成「课程体系」，只填名称也能入库。
③ 第二批含已有单词
再传 新初一单词.xlsx：name / nice / meet / friend 显示为「已存在单词」， 不重复创建基础单词；原词库排序与学员复习状态都不变。
④ 文件内重复
人教版一年级起点.xlsx 里 red / blue 各出现 3 次 → 卡片显示「文件内重复 3 行」， 只写入 7 个单词，不会重复关联。
⑤ 坏文件独立失败
同批放一个只有封面的 外研社版中学英语(全).xlsx：它自己失败并留下记录， 另外两个文件照常入库；失败行可下载 CSV。
⑥ 刷新与教师端
刷新后词库、关联、导入历史都在；进教师端「单词训练 → 选择词库」能直接选到刚导入的词库。

第三轮迭代 · 课程工作台与教学闭环 课程成为所有教学行为的上下文 · 状态五态统一 · 报告提交发布两道门
存储版本 v4
i
本轮把「功能闭环」升级为「课程闭环」。教师从课程工作台进入单词训练、莱特纳复习、21 天复习、文章训练， 所有判断记录都自动带上 courseId，不需要重复选学员； 课程结束由系统汇总成本节课教学记录，教师补评价、提交报告、发布后家长才可见。
这一轮解决的六个问题
1 · 课程工作台（唯一入口）
课程头（学员 · 第 N 课时 · 时间 · 状态）→ 四个教学入口（各带真实状态与动作）→ 本节课教学记录实时汇总 → 教师备注 → 保存并完成。从任一入口进去，courseId 一路透传，判断记录自动归属本节课。
2 · 状态只用五个词
任务型对象统一为 未开始 / 进行中 / 已完成 / 已中断 / 已取消； 废除 submitted、interrupted 这类布尔拼装。中断必须写原因，并显示「完成 8 / 20 · 剩余 12」。
3 · 状态与排期分开
21 天节点用 status 表达生命周期，用 dateState（今日 / 未到期 / 已逾期 / 休息 / 已完成）表达排期， 两个维度互不混写；模块内部阶段另用 phase（预筛选 / 强化训练 / 最后复习）。
4 · 先看现在，再看过去
单词学习档案顶部新增「当前学习全景」：当前状态、莱特纳盒位与阶段、21 天进度、最近一次训练， 下面才是完整时间轴。
5 · 教学结果，而不只是做过
文章逐句新增教师判定「掌握 / 待加强」+ 备注，课程结束汇总「总句数 / 确认掌握 / 待加强」直接进报告； 两套复习体系顶部说明「为什么今天要复习这些」。
6 · 未完成内容与可见性
课程结束时检测未完成任务，三选一：保留，下次继续（默认） / 结束本次任务 / 取消剩余内容（后两者必填说明）。 课程完成后报告为「编辑中」，须提交、再发布，家长才可见。
端到端验证路径（一节课走完）
① 进课堂
今日工作台 → 今日课程表「进入课堂」→ 课程工作台自动把课程状态改为授课中， 课程头显示学员 · 第 N 课时 · 状态，四个入口都带着 ?course=。
② 做教学
从「单词训练」入口进去建任务 → 预筛 → 强化训练判断几个词 → 回工作台， 「本节课教学记录」四格与明细表立刻出现数字，刷新不变。
③ 结束课程
点「保存并完成本节课」→ 弹窗列出未完成内容（例：单词训练 5 / 8）→ 选「保留」→ 确认 → 课程 已完成、扣 1 课时并生成流水、自动生成报告（编辑中）。
④ 写报告
跳到报告页：左栏是自动汇总，右栏是状态步骤条（未生成 → 编辑中 → 已提交 → 已发布）。 三段评价没填齐提交会被拒绝；提交后表单变只读，出现「发布给家长」。
⑤ 家长可见性
提交但未发布时，家长端只看到「老师正在整理本节课报告」；点发布后家长端才显示完整内容与逐句判定结果。
⑥ 中断与恢复
莱特纳复习点「提前结束」→ 必须填中断原因 → 卡片显示「已中断 · 完成 x / y · 原因」，可点「恢复本次复习」继续。

设计假设与待确认项PRD 未明确处，原型按下列假设实现，并显式标注
  • 1. 莱特纳算法参数（黄盒数量、间隔天数、答对/答错去向） — PRD 明确要求配置化、不写死。原型在「莱特纳复习」页提供「盒子配置」抽屉，展示为可配置项，未预设某套固定算法；复习执行页只记录结果并提示去向由配置决定。
  • 2. 21 天节点与每日上限 — PRD 列为待确认。原型时间轴展示 21 天节点与每日任务量，标注「按机构配置生成」，未固化具体节点规则。
  • 3. 两套复习体系是否默认同时加入 — 训练结果页提供两个互相独立的勾选项（默认均不勾选），并提示「是否默认同时加入由机构配置决定」。
  • 4. 佣金规则（比例 / 固定金额、确认时点、退款冲回、结算周期） — 列为待业务确认。代理详情与佣金页展示「规则待确认」状态标签，不做自动计算假设。
  • 5. 未付款订单是否可赊销加课时 — 原型按「不可」实现：订单状态为待付款时，课时账户不增加，并给出提示。
  • 6. 迟到 / 临时取消 / 缺课责任划分 — 待机构确认。课程状态含「未上课」，扣课状态独立展示，不自动扣课。
  • 7. 角色与权限 — 原型以三套菜单体现老板/教务、教师、代理，家长为移动端；权限点（如赠送课时、退款、冲正）在界面以「权限控制」标签标注，未实现完整 RBAC 配置矩阵。
  • 8. 腾讯会议链接 — 原型以「已生成 / 未生成」状态字段模拟，未接入真实 API。

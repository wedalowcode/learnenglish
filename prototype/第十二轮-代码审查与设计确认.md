# 第十二轮 · 代码审查与设计确认（教师课时费与月度结算）

- 基线：`VERSION = 9`
- 结论：**当前系统没有任何教师薪酬/课时费/结算模型**（`payment(s)` 仅指学员学费收款），必须新增独立账务链路；课程模型已有可复用字段，需扩展课型与授课形式。

---

## 一、代码审查结果

### 1. 现有课程模型字段（`db.courses`，来源 `createCourse`）
```
id, date, start, end, studentId, student, grade,
teacherId, teacher, teacherName, teacherCode,
type('一对一' 授课形式), status, deduct, deductState,
meetingUrl, meeting, note, source, seriesId, batchId, batchRowKey,
meetingPolicy, scheduleNote, scheduleWarnings,
creator, createdBy, createdAt, actualStart, actualEnd, recordId
```
- `type` 目前只承担「授课形式」（`'一对一'`），**没有课型（体验/正式）**。
- `actualStart/actualEnd` 由 `openCourse`/`finishCourse` 写入教学记录后回填。
- 判完成用 `isCourseDone`；`teacherName/teacherCode` 为授课教师快照（可复用为计费归属依据）。

### 2. 课程状态流转
`COURSE_STATUS`：`待上课(PENDING) → 授课中(ONGOING) → 已完成(DONE)`；旁支 `未上课(MISSED)`、`已取消(CANCELLED)`。
- `createCourse` 建 `待上课`；`openCourse` 进入 `授课中`；`finishCourse` 置 `已完成`（已完成不可重复完成）；`cancelCourse` 仅允许非 `已完成`。

### 3. 课程完成时的生成链路（`finishCourse`）
1. 处理未完成内容（保留/结束/取消）；
2. 写课程教学记录 `courseRecords`（`snapshot = recordSummary(r)`）；
3. `deductCourse` 扣学员课时（`accounts` + `flows`）；
4. 生成教学报告草稿 `reports`（`status=编辑中`）。
- 返回 `{course, record, report, deduct, warnings}`。

### 4. 学员扣课（`deductCourse`）
`accountsOfStudent` 取账户 → `remain-1`、`used+1` → 写 `flows`（`delta:-1, before, after, courseId`）；失败置 `deductState='扣课异常'`。
- **与教师课时费是完全独立的账务**（一个是学员预付课时，一个是机构应付教师）。

### 5. 教师工作量统计（`teacherStat`）
`doneCourses / doneHours(courseHours) / monthCourses / monthHours / monthsBy / completionRate / futureCourses` 等。
- **只有课程数量与时长，没有任何金额**；`teacherStat` 被教师列表/详情使用，扩展时需保持既有字段兼容。

### 6. 是否已有薪酬模型
**没有。** 全库检索 `teacherPay / Settlement / payRule / lessonFee / salary / 课时费 / 薪酬` 均无对应实体；`payment/payments` 属于「学员学费收款登记→入账」（订单域）。

### 7. 现有权限模型
- 角色：`admin(老板)/staff(教务)/ops(管理员)/teacher/agent/parent`。
- 权限矩阵：`db.rolePermissions` + `can()/assertCan()/hasPermission()`；菜单门控 `MENU_PERM` 与 Store 同源。
- 课程：`createCourse` 校验 `lesson.view.all`；`cancelCourse` 校验 `teacher.assign`；审计 `recordAudit`。

### 8. 新增结算能力的影响面
| 既有能力 | 影响 |
|---|---|
| 学员扣课/课时账户/流水 | 不修改，保持独立 |
| 订单/收款（学费） | 不修改，保持独立 |
| 教学记录/报告 | 不修改；`finishCourse` 仅追加计费步骤 |
| 课程列表/详情/排课 | 需增加课型/授课形式/计费状态展示与筛选 |
| `teacherStat` | 追加薪酬字段（向后兼容） |
| 审计/权限 | 需新增权限编码与审计动作 |

## 二、设计确认

### 1. Course 扩展
- `courseType`：`体验课 | 正式课 | 待确认`（**历史课程迁移为「待确认」，不默认正式课**）。
- `lessonMode`：`一对一 | 补课 | 其他`（由旧 `type` 迁移；`type` 字段保留兼容只读）。
- `teacherFeeState`：`未计费 | 已计费 | 计费异常 | 不适用`（展示/筛选）。
- 课程 `已完成` 后**锁定** `courseType / teacherId(实际授课教师) / actualStart / actualEnd`；纠错走「计费调整/冲正」，不改历史原值。

### 2. 新增模型（附加式默认，金额一律整数分）
| 模型 | 关键字段 | 唯一性 |
|---|---|---|
| `teacherPayRules` | id, teacherId, courseType, pricingMode(按小时/按节/按实际分钟), unitPriceCents, minMinutes, effectiveFrom, effectiveTo, status(启用/停用), createdBy, createdAt, updatedAt, versionOf | 同一教师+课型在同一时间区间不重叠 |
| `teacherLessonFees` | id, courseId, teacherId, studentId, courseType, lessonMode, scheduledStart/End, actualStart/End, payableMinutes, payableHours, pricingMode, unitPriceCents, amountCents, ruleId, ruleSnapshot, status(待结算/已结算/已冲正/异常), settlementId, exceptionReason, createdAt | **courseId 仅一条有效原始明细**（非 `已冲正`） |
| `teacherSettlements` | id, teacherId, periodStart, periodEnd, experienceCount/AmountCents, formalCount/AmountCents, adjustmentAmountCents, totalAmountCents, confirmedAmountCents, paidAmountCents, unpaidAmountCents, status, generatedAt, generator, version, teacherConfirmedAt/By/Amount/Version, orgConfirmedAt/By | **teacherId + periodStart + periodEnd 唯一** |
| `teacherSettlementItems` | id, settlementId, feeId, courseId, teacherId, courseType, courseDate, payableHours, unitPriceCents, amountCents, snapshot | settlementId+feeId 唯一 |
| `teacherSettlementAdjustments` | id, teacherId, settlementId, type(补发/扣减/其他), amountCents, reason, operator, reviewer, createdAt, reviewedAt, status(待审核/已审核/已驳回) | — |
| `teacherSettlementDisputes` | id, settlementId, teacherId, courseId, feeId, type, reason, expectAmountCents, submittedAt, status(待处理/处理中/已处理/已驳回), handler, handledAt, opinion, adjustmentId | — |
| `teacherPayments` | id, settlementId, teacherId, amountCents, method, paymentDate, transactionNo, proofUrl, operator, note, status(成功/失败), createdAt | — |

- 金额统一 `*Cents`（整数分）计算与累计，避免浮点误差；展示时 `/100`。
- 课程完成 → 逐节计费；结算 → 只纳入 `status=待结算` 的明细并回写 `settlementId`（防重复纳入）。

### 3. 机构级计费/结算配置（`db.config.teacherPay`）
```js
{
  settlementCycle: { startDay: 21, endDay: 20 },   // 上月21–本月20
  pricingMode: '按小时',                            // 按小时/按节/按实际分钟
  allowDecimalHours: true,                          // 是否允许小数小时
  roundMode: 'none',                                // none/floor/ceil/round（显式配置，禁止隐式）
  minBillMinutes: 0,                                // 最小计费时长
  allowExceedScheduled: false,                      // 超出预约时长是否参与计费
  missingActual: '异常',                            // 缺实际时间：异常
  legacyCourseType: '待确认'                        // 历史课程迁移默认值
}
```

### 4. 历史数据迁移
- `normalizeDb` 附加默认：旧课程补 `courseType: config.teacherPay.legacyCourseType('待确认')`、`lessonMode` 由 `type` 推导、`teacherFeeState:'未计费'`；不删除 `type`。
- 新集合补空数组与 `seq`（TPR/TLF/TS/TSI/TSA/TSD/TP）。
- 不重算历史金额；历史课程进入「待确认课型」，由管理员批量确认后方可参与正式结算。

### 5. 计费与结算规则（实现口径）
- 生成条件：仅 `已完成` 课程；`待上课/已取消/未上课` 不生成；重复完成幂等（courseId 已有有效明细则跳过）。
- 计费：按规则快照计算；`金额=单价×可计费时长/节数`；无规则/缺实际时间 → `status=异常` 进异常队列。
- 结算：按周期筛选 `待结算` 明细 → 按教师分组 → 分体验/正式课统计 → 纳入已审核调整 → 生成结算单并回写明细 `结算单 id`（幂等：teacher+period 唯一，存在则拒绝重复生成，遗漏走补充/调整）。
- 付款：只登记真实支付事实；部分付款更新 `paidAmountCents/unpaidAmountCents` 与状态；不允许登记超付（除非已审核特殊处理）。

### 6. 权限与审计
- 新增权限编码：`pay.rule.manage / pay.view.all / pay.view.own / settlement.generate / settlement.confirm_org / settlement.adjust / payment.record / dispute.handle`。
- 教师仅 `pay.view.own` + 本人确认/异议；审批与登记付款为老板/管理员。
- 审计动作：建/改/停规则、生成课时费、生成结算单、教师确认、提交/处理异议、创建/审核调整、登记/失败/撤销付款。

### 7. 待机构确认参数
结算周期是否 21–20、体验/正式单价是否按教师、计费方式、不足一小时规则、超预约时长处理、教师确认后是否需机构二次确认、对账与付款是否同日、异议期限、补录是否进已关闭周期（全部做成配置项，示例金额仅测试数据）。

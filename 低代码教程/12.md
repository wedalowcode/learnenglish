# 前言

上一节已经完成代理端“我的客户”页面，并实现了客户报备和客户跟进功能。

代理可以新增客户，系统自动绑定当前代理；代理也可以通过跟进弹窗，记录每一次沟通内容、跟进方式和下次跟进时间。

但是，客户跟进只是招生业务的过程，并不是最终目的。

代理持续跟进客户后，通常会出现两种结果：

1. **转化成功：** 家长已经确认报名意向，代理需要记录转化时间和预估成交金额。
2. **转化失败：** 客户暂时没有报名，代理需要记录失败原因，为后续分析招生情况提供依据。

本篇继续完善“我的客户”页面，在表格操作列增加两个按钮：

- 标记成功
- 标记失败

点击“标记成功”，打开转化成功弹窗，填写转化时间和预估成交金额。

点击“标记失败”，打开转化失败弹窗，选择失败原因，并保存。

两个操作统一使用一个前端自定义方法完成数据更新。

本篇还会扩展客户表的数据模型，并提前设计转化成功后使用的学员表。

完成本篇后，代理可以完成从客户报备、客户跟进到招生转化的业务闭环。

需要说明的是：本篇只完成客户转化，不实现教务建档。成功转化的客户将作为后续教务建档的数据来源。

# 一、先梳理招生转化业务流程

## 1.1 数据模型设计

回顾上一节，我们已经建立了两张核心数据表：

**客户表 `biz_customer`**

用于保存代理报备的客户基本信息。

**客户跟进记录表 `biz_customer_follow_up`**

用于保存代理与客户每一次沟通的过程。

两张表之间通过 `customer_id` 关联。

业务关系如下：

```text
代理 biz_agent
     │
     │ 一对多
     ▼
客户 biz_customer
     │
     │ 一对多
     ▼
客户跟进记录 biz_customer_follow_up
```

一个代理可以报备多个客户，一个客户可以有多条跟进记录。

这样我们就可以完整保留客户的沟通过程。

## 2.2 本篇需要增加什么？

当代理认为客户已经完成招生转化时，需要在客户记录上执行标记操作。

例如：

```text
客户：王同学家长
所属代理：张三
联系电话：138XXXXXXXX
学生年级：五年级
意向课程：英语一对一
        │
        ▼
代理持续跟进
        │
        ├── 标记成功
        │      ├── 转化时间：2026-11-24
        │      └── 预估成交金额：4800
        │
        └── 标记失败
               └── 失败原因：价格原因
```

这里有一个设计问题：

转化结果属于客户当前的业务状态，而不是一次沟通记录。

因此，转化结果和转化信息应该保存在客户表中，而不是再创建一张转化记录表。

客户跟进记录表负责记录每一次沟通。

客户表负责记录当前客户的最新状态和转化结果。

## 2.3 本篇完成后的业务流程

```text
代理登录
   │
   ▼
我的客户
   │
   ▼
新增客户报备
   │
   ▼
记录客户跟进
   │
   ▼
判断是否完成招生转化
   │
   ├──────────────┐
   │              │
   ▼              ▼
标记成功         标记失败
   │              │
   ▼              ▼
填写转化信息     选择失败原因
   │              │
   ▼              ▼
保存客户状态     保存客户状态
   │              │
   └──────┬───────┘
          │
          ▼
     更新我的客户列表
```

本篇暂时不实现成功转化后的学员建档。

后续由教务人员根据转化成功的客户，创建正式学员档案。

# 二、扩展客户表数据模型

## 2.1 为什么需要扩展客户表？

第10篇已经创建了客户表 `biz_customer`。

第11篇又增加了客户跟进记录表。

现在我们需要在原有客户表中增加转化相关字段，而不是重新创建一张客户转化表。

这样做有两个好处：

1. 客户基本资料、跟进状态和转化结果都集中在一条客户记录中。
2. 后续管理端可以直接查询客户表，统计代理的转化数量和预估成交金额。

## 2.2 客户表新增字段

进入微搭控制台，打开数据模型管理。

找到原有客户表：

`biz_customer`

在原有字段基础上，新增以下字段。

| 字段标识 | 字段名称 | 字段类型 | 说明 |
|---|---|---|---|
| `converted_at` | 转化时间 | 日期时间 | 标记成功时记录 |
| `expected_amount` | 预估成交金额 | 数字 | 预计成交金额 |
| `fail_reason` | 失败原因 | 枚举 | 标记失败时选择 |


## 2.3 配置失败原因枚举

找到 `fail_reason` 字段，将字段类型设置为枚举。

失败原因建议设置为以下选项：

| 选项标识 | 选项值 |
|---|---|
| `1` | 价格原因 |
| `2` | 时间安排不合适 |
| `3` | 课程不匹配 |
| `4` | 选择其他机构 |
| `5` | 暂无学习需求 |
| `6` | 多次联系未回复 |
| `7` | 其他原因 |

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/9c30208a584f43f4b730b08605331971.png)


为什么不直接使用文本字段？

因为失败原因是后续招生分析的重要数据。

如果让代理自由填写，可能出现：

- 价格太高
- 觉得贵
- 费用问题
- 价格原因

这些描述实际上是同一类原因，却无法直接进行准确统计。

使用枚举值可以统一数据口径。

如果选择“其他原因”，可以在转化备注中补充具体情况。

## 2.4 其他字段配置说明

`converted_at` 使用日期时间类型。

`expected_amount` 使用数字类型，建议保留两位小数。

这里要注意：

**预估成交金额不等于实际收款金额。**

客户可能已经确认报名，但还没有付款；也可能后续实际成交金额与最初预估不同。

因此，本篇只记录预估成交金额，后续订单和收款功能需要独立设计。

## 3.4 为什么使用两个弹窗？

两个操作虽然最终都要更新客户表，但需要填写的内容并不一样。

成功操作需要转化时间和预估金额。

失败操作需要失败原因。

如果把所有字段都放在同一个弹窗中，代理每次操作都需要面对不相关的字段，使用体验不好。

因此，本篇使用两个弹窗分别承载两种业务操作。

不过，弹窗只是负责收集数据，真正的数据更新逻辑统一放在一个自定义方法中。

# 本篇总结

本篇在第11篇客户跟进功能的基础上，继续完成了招生转化。

主要完成了四件事：

1. 扩展客户表，增加转化状态、转化时间、预估成交金额和失败原因等字段。
2. 在“我的客户”操作列增加标记成功和标记失败两个按钮。
3. 使用两个弹窗收集不同的转化信息，并通过一个前端自定义方法统一更新客户表。


这里需要记住三个业务对象的区别：

- 客户：招生阶段的业务对象。
- 学员：正式进入教学服务阶段的业务对象。
- 家长：学员的监护人或主要联系人。

客户转化成功只是招生环节完成，并不意味着学员档案、订单和课时账户已经建立。

下一篇可以继续围绕教务端展开：建立待建档客户列表，由教务人员将转化成功的客户正式创建为学员档案。

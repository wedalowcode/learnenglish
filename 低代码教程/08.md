# 前言

上一节已经完成了词库单词管理页面，实现了当前词库关联单词的查询和移除。

目前，我们可以查看一本教材包含哪些单词，也可以将不需要的单词从当前词库中移除。

但是，词库管理还缺少一个重要功能：从基础单词表中选择单词，批量添加到当前词库。

例如，我们已经创建了一个“人教版三年级上册”词库，基础单词表中也已经整理了 apple、book、cat 等单词。

现在需要实现这样的操作：

1. 点击词库单词管理页面中的“添加单词”按钮。
2. 打开弹窗，展示基础单词表中的单词。
3. 勾选需要添加的单词。
4. 点击确定，将选中的单词批量加入当前词库。
5. 如果某个单词已经存在于当前词库，则自动跳过，避免重复关联。

本篇继续完善第七篇创建的词库单词管理页面，重点实现单词选择、批量添加和重复数据检查。

这里有一个重要的设计原则：

**添加单词不是向基础单词表新增数据，而是在词库单词关联表中建立新的关联关系。**

这样，不同教材可以复用同一条基础单词记录，不需要重复保存相同的单词。

# 二、理解关联查询与批量查重

在编写批量添加代码之前，需要先理解一个问题：

**如何判断用户选择的单词是否已经存在于当前词库？**

## 1. 为什么不能查询整个词库？

假设当前词库已经有 5000 个单词，用户这次只选择了 5 个单词。

如果每次添加都先查询整个词库，就需要：

- 每页读取 200 条记录；
- 一共请求 25 次；
- 将 5000 条关联记录传回前端；
- 再从中筛选出已经存在的单词。

这显然没有必要。

我们真正需要查询的是：

当前词库中，是否已经存在用户本次选择的这几个单词。

因此，应该将查询范围限定在本次选择的单词集合内。

## 2. 理解 relateWhere 关联查询

微搭的数据模型支持通过 `relateWhere` 对关联表进行条件查询。

官方文档中的示例，是通过关联字段查询符合条件的主表记录。

例如，学生表关联教师表，可以根据教师姓名查询学生：

```javascript
filter: {
  relateWhere: {
    teacher_id: {
      where: {
        name: {
          $eq: "li"
        }
      }
    }
  }
}
```

这里的 `teacher_id` 是关联字段，`where` 中的条件作用于被关联的教师表。

官方文档：

https://docs.cloudbase.net/lowcode/api/model_relation

我们的 `biz_wordbook_word` 关联表中有两个关联字段：

- `wordbook_id`：关联词库表。
- `word_id`：关联基础单词表。

因此，可以使用 `relateWhere` 同时限定这两个关联关系。

## 3. 理解 $in 批量匹配

微搭还提供了 `$in` 查询运算符。

例如：

```javascript
where: {
  _id: {
    $in: ["word_001", "word_002", "word_003"]
  }
}
```

表示查询 ID 属于指定数组的记录。

这与 SQL 中的 `IN` 操作类似。

因此，我们可以组合两个查询条件：

- 词库 ID 等于当前词库 ID。
- 单词 ID 属于用户本次选择的单词 ID 集合。

逻辑上相当于：

```sql
SELECT *
FROM biz_wordbook_word
WHERE wordbook_id = 当前词库ID
AND word_id IN (本次选择的单词ID);
```

这里需要注意，实际使用的是微搭关联查询语法，而不是直接对关联字段使用普通 `where`。

另外，微搭官方建议 `$in` 数组中的值不超过 100 个。因此，后续代码会按照每组 100 个单词进行分批查询。

## 2. 获取当前词库 ID 和选中单词

首先需要获取两个信息：

当前词库 ID：

```javascript
const wordbookId = $w.page.dataset.params?.wordbookId;
```

用户选中的基础单词：

```javascript
const selectedRecords = $w.table2.selectedRecords || [];
```

从选中记录中提取单词 ID：

```javascript
const selectedWordIds = selectedRecords
  .map(item => item._id)
  .filter(Boolean);
```

这样，我们就得到了本次需要检查的单词 ID 数组。

## 3. 按每组 100 个单词查询已有关系

创建一个 Set，用来保存已经存在于当前词库中的单词 ID：

```javascript
const existingWordIds = new Set();
```

接下来对 `selectedWordIds` 进行分组，每组最多 100 个。

```javascript
const batchSize = 100;

for (let i = 0; i < selectedWordIds.length; i += batchSize) {
  const ids = selectedWordIds.slice(i, i + batchSize);

  // 查询当前词库中，这一组单词已经存在的关联记录
}
```

例如，用户选择了 230 个单词，那么查询过程就是：

- 第一次查询 100 个；
- 第二次查询 100 个；
- 第三次查询 30 个。

查询次数只取决于本次选择的单词数量，不再取决于整个词库已经有多少条记录。

## 4. 编写完整批量添加代码

在 `addWordsToBook` 方法中编写以下代码：

```javascript
export default async function ({ event, data }) {
  try {
    // 1. 获取当前词库 ID
    const wordbookId = $w.page.dataset.params?.wordbookId;

    if (!wordbookId) {
      $w.utils.showToast({
        title: '缺少词库ID',
        icon: 'error',
        duration: 2000,
      });
      return;
    }

    // 2. 获取用户选中的基础单词
    const selectedRecords = $w.table2.selectedRecords || [];

    if (selectedRecords.length === 0) {
      $w.utils.showToast({
        title: '请选择单词',
        icon: 'error',
        duration: 2000,
      });
      return;
    }

    // 3. 提取单词 ID，并去除重复值
    const selectedWordIds = [
      ...new Set(
        selectedRecords
          .map(item => item._id)
          .filter(Boolean)
      )
    ];

    if (selectedWordIds.length === 0) {
      $w.utils.showToast({
        title: '没有有效单词',
        icon: 'error',
        duration: 2000,
      });
      return;
    }

    // 4. 创建 Set，保存已经关联的单词 ID
    const existingWordIds = new Set();

    // 5. 每组最多查询 100 个单词
    const batchSize = 100;

    for (let i = 0; i < selectedWordIds.length; i += batchSize) {
      const ids = selectedWordIds.slice(i, i + batchSize);

      const result = await $w.cloud.callDataSource({
        dataSourceName: 'biz_wordbook_word',
        methodName: 'wedaGetRecordsV2',
        params: {
          filter: {
            relateWhere: {
              wordbook_id: {
                where: {
                  _id: {
                    $eq: wordbookId,
                  },
                },
              },
              word_id: {
                where: {
                  _id: {
                    $in: ids,
                  },
                },
              },
            },
          },
          select: {
            $master: true,
            word_id: true,
          },
          pageSize: 100,
          pageNumber: 1,
          getCount: true,
          getRecords: true,
        },
      });

      // 6. 提取已经存在的基础单词 ID
      const records = result?.records || [];

      records.forEach(item => {
        const wordId = typeof item.word_id === 'string'
          ? item.word_id
          : item.word_id?._id;

        if (wordId) {
          existingWordIds.add(wordId);
        }
      });
    }

    // 7. 过滤掉已经关联的单词
    const newWords = selectedRecords.filter(item => {
      return item._id && !existingWordIds.has(item._id);
    });

    // 8. 判断是否还有需要添加的单词
    if (newWords.length === 0) {
      $w.utils.showToast({
        title: '单词已存在',
        icon: 'none',
        duration: 2000,
      });
      return;
    }

    // 9. 生成关联表数据
    const newRecords = newWords.map(item => ({
      wordbook_id: {
        _id: wordbookId,
      },
      word_id: {
        _id: item._id,
      },
    }));

    // 10. 批量创建关联记录
    const createResult = await $w.cloud.callDataSource({
      dataSourceName: 'biz_wordbook_word',
      methodName: 'wedaBatchCreateV2',
      params: {
        data: newRecords,
      },
    });

    // 11. 检查批量新增结果
    const idList = createResult?.idList || [];

    if (idList.length !== newRecords.length) {
      console.error('批量新增返回结果:', createResult);
      throw new Error('添加结果异常，请检查数据');
    }

    // 12. 提示添加结果
    const skippedCount = selectedRecords.length - newWords.length;

    $w.utils.showToast({
      title: skippedCount > 0
        ? `添加${newWords.length}个，跳过${skippedCount}个`
        : `成功添加${newWords.length}个单词`,
      icon: 'success',
      duration: 2000,
    });

    // 13. 关闭弹窗
    $w.modal1.close({});

    // 14. 清空选择状态
    $w.table2.clearSelection();

    // 15. 刷新当前词库单词列表
    $w.table1.refreshKeepPage();

  } catch (error) {
    console.error('添加词库单词失败:', error);

    $w.utils.showToast({
      title: error?.message || '添加失败',
      icon: 'error',
      duration: 2000,
    });
  }
}
```

注意：上面的代码使用 `result.records` 获取查询结果，并通过 `word_id._id` 提取关联单词 ID。微搭关联查询示例支持通过 `select` 携带关联字段，但实际返回结构仍应以当前环境的运行结果为准。如果返回的关联字段结构不同，需要相应调整提取逻辑。

## 5. 理解这段代码的几个关键点

**第一，为什么使用 relateWhere？**

因为我们需要根据关联表中的两个关联字段进行筛选。

`relateWhere` 可以让查询条件作用于关联的数据模型，而不只是关联表自身的普通字段。

本例中：

```javascript
wordbook_id: {
  where: {
    _id: {
      $eq: wordbookId,
    },
  },
}
```

用于限定当前词库。

而：

```javascript
word_id: {
  where: {
    _id: {
      $in: ids,
    },
  },
}
```

用于限定本次选择的基础单词。

两个条件同时满足，才会返回对应的关联记录。

**第二，为什么使用 Set？**

查询结果只包含本次选择中已经存在的关联记录。

我们把这些单词 ID 放入 Set：

```javascript
existingWordIds.add(wordId);
```

然后通过：

```javascript
!existingWordIds.has(item._id)
```

过滤掉已经存在的单词。

Set 适合用于这种集合成员判断，代码简单，也不需要反复遍历数组。

**第三，为什么每组最多 100 个？**

因为微搭官方文档建议 `$in` 列表中的值不宜过多，建议不超过 100 个。

因此，我们使用：

```javascript
const batchSize = 100;
```

控制每次查询的数据规模。

如果用户一次选择 300 个单词，就分成三次查询。

需要注意，这里的分批是按照本次选择的单词数量进行的，而不是按照当前词库已有数据量进行的。

**第四，为什么使用 wedaBatchCreateV2？**

过滤重复数据后，剩余的单词会被转换为关联表记录：

```javascript
{
  wordbook_id: {
    _id: wordbookId,
  },
  word_id: {
    _id: item._id,
  },
}
```

然后通过 `wedaBatchCreateV2` 一次性创建。

这样可以减少逐条新增产生的接口调用。

**第五，为什么不在这里设置 seq？**

`seq` 用于保存单词在词库中的排序位置。

如果直接使用 `index + 1`，新添加的单词可能与已有单词的排序值重复。

而要正确追加排序，就需要额外获取当前词库已有的最大排序值，或者设计专门的排序规则。

本篇先完成单词关联功能，不在没有确定排序规则的情况下写入可能重复的排序值。后续再单独完善词库单词排序。

# 总结

本篇在上一节的基础上，为词库单词管理页面增加了批量添加功能。

现在，词库管理已经具备三个基本能力：

1. 根据当前词库 ID 查询已经关联的单词。
2. 从基础单词表中选择单词，批量建立关联。
3. 从当前词库移除单词，但保留基础单词记录。

本篇涉及的核心技术包括：

- 弹窗组件：通过 `open()` 和 `close()` 控制弹窗。
- 数据表格多选：通过 `selectedRecords` 获取选中记录。
- `relateWhere`：根据关联模型中的字段进行查询。
- `$in`：一次匹配多个单词 ID。
- Set：判断单词是否已经存在。
- `wedaBatchCreateV2`：批量创建词库单词关联数据。
- `clearSelection()`：清空表格选中状态。
- `refreshKeepPage()`：刷新当前词库单词列表。

至此，我们已经完成了词库单词管理的基本闭环。

基础单词统一保存在 `biz_word` 中，不同教材通过 `biz_wordbook_word` 建立关联。一本教材可以收录多个单词，同一个基础单词也可以被多本教材复用。

这种设计避免了不同教材重复保存相同单词，也为后续教材词库自动化初始化打下了基础。

下一步，可以结合 WorkBuddy 自动整理教材单词，匹配已有基础单词，补充缺失词条，再自动建立词库与单词之间的关联，让教材词库从人工逐条维护逐步转向自动化初始化。

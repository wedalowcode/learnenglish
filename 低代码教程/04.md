# 前言

上一篇我们使用微搭的数据模型和页面模板，完成了教师管理功能。

整个过程没有编写云函数，也没有手动实现数据查询、创建、修改和删除逻辑，而是通过数据模型和「表格与表单页」模板，快速搭建了一套标准的 CRUD 管理功能。

本篇继续使用相同的方式，搭建代理管理功能。

在英语教学平台中，代理是重要的业务参与者。

平台通过代理招募家长、拓展学员，并根据业务规则进行代理等级管理和上下级关系维护。

与教师相比，代理除了姓名、手机号等基本信息之外，还具有两个比较重要的业务属性：

- 代理等级：用于区分不同级别的代理。
- 上级代理：用于记录代理之间的上下级关系。

因此，本篇先完成代理基础信息管理，实现代理列表、新增代理、编辑代理和删除代理等功能。

本篇主要学习三个内容：

1. 如何根据业务需求设计代理数据模型。
2. 如何在微搭中创建代理数据模型及字段。
3. 如何使用页面模板生成代理管理页面，并配置到管理应用菜单中。

最终实现的功能包括：

- 代理列表：查看代理基本信息。
- 新增代理：录入代理资料。
- 编辑代理：修改代理基本信息。
- 删除代理：删除测试或无效的代理记录。

# 一、回顾代理数据模型结构

在开始创建数据模型之前，先回顾一下前面设计的代理业务表。

本项目中，代理对应的数据模型为 `biz_agent`。

为什么需要单独建立代理业务表？

因为代理虽然需要通过微搭外部用户认证体系登录，但代理本身还具有独立的业务属性，例如代理等级、上级代理、业务状态等。

这些信息属于业务数据，不应该直接依赖微搭系统用户表保存。

因此，我们建立独立的代理业务模型，用来管理代理的业务资料。

前面设计的代理表结构如下：

| 字段名称 | 字段标识 | 字段类型 | 说明 |
|---|---|---|---|
| 主键 | `_id` | 系统字段 | 代理记录唯一标识 |
| 代理姓名 | `name` | 文本 | 代理姓名 |
| 手机号 | `phone` | 电话 | 联系电话 |
| 微搭用户ID | `user_id` | 文本 | 关联微搭认证用户 |
| 代理状态 | `status` | 枚举 | 启用、停用 |
| 代理等级 | `agent_level` | 枚举 | 代理等级，设置为普通代理、核心代理、合伙人 |
| 上级代理 | `superior_id` | 关联关系 | 保存上级代理记录标识 |
| 备注 | `remark` | 文本 | 其他说明 |


![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/9b6aba48f35e4520b46a7f6c1f4c3f90.png)



这里有三个字段需要重点说明。

**1. user_id：微搭用户ID**

这个字段保存代理绑定的微搭认证用户 ID。

与教师管理中的 `user_id` 一样，必须使用文本类型，不要创建成系统用户表的关联字段。

原因是微搭系统内置用户表不允许我们直接建立关联关系。

后续代理首次登录时，可以根据手机号找到对应的代理业务记录，再通过服务端身份校验完成 `user_id` 绑定。

**2. agent_level：代理等级**

这个字段用于记录代理的业务等级。

不同等级可以对应不同的业务政策，例如招生权限、佣金规则等。

代理等级可以设置为普通代理、核心代理、合伙人

**3. superior_id：上级代理**

这个字段用于记录当前代理的上级代理。

这里保存的是代理业务记录的标识，而不是微搭认证用户 ID。

例如，代理 A 的上级代理是代理 B，那么代理 A 的 `superior_id` 保存的就是代理 B 的业务记录 ID。

后续我们会围绕这个字段实现代理之间的上下级关系。

另外，`_id` 是数据模型的系统主键，由微搭自动生成，不需要手动创建。

# 二、创建代理数据模型

了解了代理的数据结构，接下来进入微搭控制台创建数据模型。

## 2.1 进入数据模型

打开英语教学平台管理应用。

点击左侧导航菜单中的 SQL 数据模型，选择数据模型页签。

点击「创建数据模型」，选择添加模型。
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/bd25a018378746ceb2d8aaf14897abd5.png)

数据模型名称填写：

`代理表`

数据模型标识填写：

`biz_agent`

本项目统一使用 `biz_` 作为业务数据模型的前缀。

目前已经创建的业务模型包括：

- `biz_coach`：教师
- `biz_agent`：代理

后续还会创建家长、学员、课程、订单等业务模型。

统一命名规则可以让整个项目的数据结构更加清晰。

## 2.2 创建字段

数据模型创建完成后，开始添加代理字段。

按照前面设计的表结构，依次创建以下字段。

**代理姓名**

字段名称：代理姓名

字段标识：`name`

字段类型：文本。

用于保存代理的姓名。

如果数据模型支持设置主列字段，建议将代理姓名设置为主列字段。

这样后续在其他业务表单中选择代理时，可以直接显示代理姓名，而不是一串难以识别的记录 ID。

**手机号**

字段名称：手机号

字段标识：`phone`

字段类型：电话。

用于保存代理联系电话。

手机号虽然由数字组成，但它本质上是联系方式，不需要进行数学计算，因此不应该使用数字类型。

**微搭用户ID**

字段名称：微搭用户ID

字段标识：`user_id`

字段类型：文本。

这个字段用于保存代理绑定的微搭认证用户 ID。

注意，这里不要创建成关联字段。

**代理状态**

字段名称：代理状态

字段标识：`status`

字段类型：枚举。

创建选项集，先设置两个选项：

- 启用
- 停用

后续代理暂时不参与业务时，可以将状态修改为停用，而不是直接删除代理记录。

**代理等级**

字段名称：代理等级

字段标识：`agent_level`

字段类型：枚举。

根据实际业务情况创建代理等级选项集。

例如，可以根据机构的代理政策设置不同等级。具体等级名称不在本篇固定，后续可以结合实际的代理制度进行调整。

**上级代理**

字段名称：上级代理

字段标识：`superior_id`

字段类型：关联关系。

用于保存上级代理对应的业务记录 ID。

这里需要区分两个 ID：

- `user_id`：微搭认证用户 ID。
- `superior_id`：上级代理的业务记录 ID。

两者用途完全不同，不要混淆。

本篇先使用文本字段保存上级代理标识，暂时不实现上下级代理的选择和维护功能。

**备注**

字段名称：备注

字段标识：`remark`

字段类型：文本。

用于记录代理的其他说明信息。

字段创建完成后，检查字段标识和数据类型，确认无误后保存数据模型。

数据模型权限需要根据实际业务职责配置。代理资料由管理端内部人员统一维护，因此要确保有权限的管理员和教务能够查看和管理全部代理记录。不要仅因为创建了数据模型，就默认所有用户都具备完整的数据操作权限。

# 三、根据数据模型创建代理管理页面

数据模型创建完成之后，接下来创建代理管理页面。

与教师管理一样，我们继续使用微搭提供的「表格与表单页」模板。

回到管理应用的页面设计界面。

点击创建页面，选择根据模板生成。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/eef2b141b9504b77b2f0320e845dfe33.png)

在模板列表中找到：

**表格与表单页**

选择该模板。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/5006dd4723c04667a5208ea00ed090c6.png)


这个模板适合基础信息管理场景，可以根据数据模型生成列表和表单页面。

## 3.2 选择数据模型

选择表格与表单页之后，根据页面创建向导配置数据模型。

数据模型选择刚才创建的：

`biz_agent`

`代理管理`

`左侧导航布局`

与手动创建页面相比，这种方式可以减少大量重复配置工作。

## 3.3 理解生成的页面结构

页面生成完成后，进入页面设计界面。

可以看到，微搭已经根据代理数据模型生成了对应的基础页面。

通常包括：

- 代理列表页面：展示代理记录。
- 编辑页面：实现新增和修改。
- 查看页面：展示代理详细信息。

后续遇到实际业务需求时，再逐步调整字段展示、查询条件和表单布局。

# 本篇总结

本篇使用微搭数据模型和页面模板，完成了代理管理的基础功能。

整个过程与教师管理类似：

1. 根据业务需求设计代理数据模型。
2. 在微搭中创建 `biz_agent` 数据模型。
3. 按照业务字段创建对应字段。
4. 使用表格与表单页模板生成管理页面。
5. 将代理管理页面添加到教务工作区菜单。
6. 通过实时预览验证基础增删改查功能。

不过，代理管理与教师管理还有一个重要区别。

教师主要围绕授课、课程安排和课时记录开展业务；代理则存在等级和上下级关系，后续还需要管理代理与家长、学员之间的业务关系。

因此，本篇只是完成代理基础信息管理，并没有提前实现复杂的代理业务逻辑。

后续我们会继续完善：

- 代理账号与微搭用户身份绑定。
- 代理上下级关系维护。
- 代理与家长之间的归属关系。
- 代理招生和订单统计。
- 代理等级及相关业务规则。

**本篇的核心仍然是掌握微搭标准 CRUD 的搭建方法。只要数据模型设计合理，很多基础管理功能都可以通过模板快速生成，不需要重复开发。**

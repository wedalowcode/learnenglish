前面已经完成管理应用，以及教师、代理、词库和单词等基础数据模型。

接下来开始建设面向外部业务人员的 Web 工作应用。

本篇先解决代理登录和身份识别问题。

我们采用以下技术方案：

- 前端通过 `$w.auth.getUserInfo()` 获取当前登录用户信息。
- 前端通过 `$w.cloud.callFunction()` 调用云函数。
- 云函数使用 `@cloudbase/node-sdk` 获取当前调用者身份。
- 云函数通过 `app.models` 查询和更新 `biz_agent`。
- 首次登录根据手机号匹配代理记录，完成 `user_id` 绑定。
- 后续登录通过用户 ID 识别代理。
- 验证通过后，返回代理业务记录 ID，进入代理工作台。

本篇不使用已经下线的旧 APIs 自定义方法方案。

# 二、明确代理身份绑定规则

在编写代码之前，先回顾代理表 `biz_agent`。

已经创建的字段包括：

| 字段 | 用途 |
|---|---|
| _id | 代理业务记录 ID |
| name | 代理姓名 |
| phone | 代理手机号 |
| user_id | 绑定的微搭用户 ID |
| status | 启用或停用 |
| agent_level | 代理等级 |
| superior_id | 上级代理业务记录 ID |

其中，`user_id` 是身份绑定的关键字段。

## 1. 首次登录

假设管理员已经创建代理记录：

| name | phone | user_id | status |
|---|---|---|---|
| 张老师 | 13800138000 | 空 | 启用 |

张老师通过手机号验证码登录 Web 应用。

前端获取当前登录用户：

```javascript
const userInfo = await $w.auth.getUserInfo();

console.log(userInfo);
```

微搭用户信息中包含：

```javascript
{
  type: 1,
  phone: "13800138000",
  userId: "微搭用户ID",
  userType: "externalUser"
}
```

这里：

- `phone`：当前登录手机号。
- `userId`：微搭用户 ID。
- `type`：用户类型，1 表示外部用户。

## 2. 首次绑定后

代理记录变成：

| name | phone | user_id | status |
|---|---|---|---|
| 张老师 | 13800138000 | 已绑定用户ID | 启用 |

以后张老师再次登录，不再通过手机号匹配，而是通过 `user_id` 查询代理记录。

这样即使更换手机号，只要微搭账号没有变化，业务身份仍然有效。

## 3. 身份验证规则

| 场景 | 处理结果 |
|---|---|
| user_id 已绑定当前用户 | 允许进入 |
| user_id 未绑定，手机号匹配一条启用记录 | 首次绑定 |
| 手机号没有匹配记录 | 提示尚未开通 |
| 手机号匹配多条记录 | 提示数据异常 |
| 代理已经绑定其他用户 | 拒绝绑定 |
| 代理已停用 | 拒绝进入 |

这里还有一个重要原则：

**手机号只负责首次匹配，user_id 才是后续业务身份关联依据。**

## 3. 理解云函数初始化

在 `index.js` 中，首先初始化 CloudBase：

```javascript
const cloudbase = require('@cloudbase/node-sdk');

const app = cloudbase.init({
  env: cloudbase.SYMBOL_CURRENT_ENV,
});
```

这里有三个概念：

- `@cloudbase/node-sdk`：CloudBase 服务端 SDK。
- `cloudbase.init()`：初始化 CloudBase 应用实例。
- `SYMBOL_CURRENT_ENV`：使用当前云函数所在的环境，不需要在代码中写死环境 ID。

初始化完成后：

```javascript
const models = app.models;
const auth = app.auth();
```

`models` 用来访问微搭数据模型，`auth` 用来获取当前调用者的身份。

## 4. 编写云函数完整代码

打开 `index.js`，编写以下代码：

```javascript
const cloudbase = require('@cloudbase/node-sdk');

const app = cloudbase.init({
    env: cloudbase.SYMBOL_CURRENT_ENV,
});

// 代理表模型标识
const MODEL = 'biz_agent';

exports.main = async (event, context) => {
    const models = app.models;
    const auth = app.auth();

    try {
        // 1. 获取云函数当前调用者的真实身份
        const currentUser = auth.getUserInfo();
        const uid = currentUser && currentUser.uid;

        if (!uid || currentUser.isAnonymous) {
            return {
                ok: false,
                message: '请先登录',
            };
        }
        console.log('当前调用者身份:', auth.getUserInfo());
        console.log('前端传入身份:', {
            userId: event.userId,
            phone: event.phone,
        });
        // 2. 获取前端传入的信息
        const phone = event && event.phone;
        const userId = event && event.userId;

        if (!phone || !userId) {
            return {
                ok: false,
                message: '登录信息不完整',
            };
        }

        // 3. 检查前端 userId 与服务端 uid 是否一致
        // 只有确认一致，才允许继续绑定
        if (uid !== userId) {
            console.error('身份标识不一致', {
                uid,
                userId,
            });

            return {
                ok: false,
                message: '用户身份校验失败',
            };
        }

        // 4. 通过手机号反查 CloudBase 用户
        // 验证前端传来的手机号确实属于当前登录账号
        console.log("通过手机号反查 CloudBase 用户")
        /*const phoneUserResult = await auth.queryUserInfo({
            platform: 'PHONE',
            platformId: phone,
        });

        const phoneUser = phoneUserResult &&
            phoneUserResult.userInfo;

        if (!phoneUser || phoneUser.uid !== uid) {
            return {
                ok: false,
                message: '手机号身份校验失败',
            };
        }*/

        // 5. 优先根据 user_id 查询代理记录
        const userResult = await models[MODEL].list({
            filter: {
                where: {
                    user_id: {
                        $eq: userId,
                    },
                },
            },
            select: {
                $master: true,
            },
            pageSize: 2,
            getCount: true,
        });

        const userRecords =
            userResult?.data?.records ||
            userResult?.records ||
            [];

        // 同一个用户不能绑定多条代理记录
        if (userRecords.length > 1) {
            return {
                ok: false,
                message: '代理账号绑定异常',
            };
        }

        // 6. 已经绑定，直接检查状态
        if (userRecords.length === 1) {
            const agent = userRecords[0];

            if (agent.status !== '1') {
                return {
                    ok: false,
                    message: '代理账号已停用',
                };
            }

            return {
                ok: true,
                message: '身份验证成功',
                agentId: agent._id,
                agentName: agent.name,
                firstBind: false,
            };
        }

        // 7. 尚未绑定，根据手机号查询代理记录
        const phoneResult = await models[MODEL].list({
            filter: {
                where: {
                    phone: {
                        $eq: phone,
                    },
                },
            },
            select: {
                $master: true,
            },
            pageSize: 2,
            getCount: true,
        });

        const agents =
            phoneResult?.data?.records ||
            phoneResult?.records ||
            [];

        if (agents.length === 0) {
            return {
                ok: false,
                message: '尚未开通代理身份',
            };
        }

        if (agents.length > 1) {
            return {
                ok: false,
                message: '手机号对应多条代理记录',
            };
        }

        const agent = agents[0];
        console.log("agent", agent)
        // 8. 检查代理状态
        if (agent.status !== '1') {
            return {
                ok: false,
                message: '代理账号已停用',
            };
        }

        // 9. 检查代理是否已经绑定其他账号
        if (agent.user_id && agent.user_id !== userId) {
            return {
                ok: false,
                message: '该代理已绑定其他账号',
            };
        }

        // 10. 首次绑定
        // 使用 user_id 为空作为更新条件，防止覆盖其他账号
        await models[MODEL].update({
            data: {
                user_id: userId,
            },
            filter: {
                where: {
                    _id: {
                        $eq: agent._id,
                    },
                },
            },
        });

        // 11. 重新查询，确认绑定结果
        const verifyResult = await models[MODEL].list({
            filter: {
                where: {
                    _id: {
                        $eq: agent._id,
                    },
                    user_id: {
                        $eq: userId,
                    },
                },
            },
            select: {
                $master: true,
            },
            pageSize: 1,
        });

        const verifyRecords =
            verifyResult?.data?.records ||
            verifyResult?.records ||
            [];

        if (verifyRecords.length !== 1) {
            return {
                ok: false,
                message: '账号绑定失败，请联系管理员',
            };
        }

        return {
            ok: true,
            message: '首次绑定成功',
            agentId: agent._id,
            agentName: agent.name,
            firstBind: true,
        };

    } catch (error) {
        console.error('代理身份验证失败:', error);

        return {
            ok: false,
            message: error.message || '代理身份验证失败',
        };
    }
};
```

## 5. 理解这段代码的关键逻辑

代码虽然比较长，但实际可以分成四个阶段。

**第一阶段：验证当前登录用户**

```javascript
const currentUser = auth.getUserInfo();
const uid = currentUser && currentUser.uid;
```

这里不是读取前端传过来的用户 ID，而是通过云函数中的认证对象获取当前调用者身份。

前端传来的 `userId` 需要与服务端 `uid` 比较。

只有一致才继续执行。

**第二阶段：优先通过 user_id 查询**

```javascript
const userResult = await models[MODEL].list({
  filter: {
    where: {
      user_id: {
        $eq: userId,
      },
    },
  },
});
```

已经绑定的用户直接找到自己的代理记录。

只有查询不到时，才通过手机号进行首次匹配。

**第三阶段：首次绑定**

```javascript
await models[MODEL].update({
  data: {
    user_id: userId,
  },
  filter: {
    where: {
        {
          _id: {
            $eq: agent._id,
          },
        },
    },
  },
});
```

更新完成后再查询一次，确认绑定成功。

这个方法负责：

2. 获取手机号和用户 ID。

4. 处理云函数返回结果。
5. 验证成功后进入代理首页。

## 1. 编写前端代码

```javascript
export default async function ({ event, data }) {
  try {
    // 1. 获取当前登录用户信息
    const userInfo = await $w.auth.getUserInfo();

    if (
      !userInfo ||
      userInfo.type !== 1 ||
      userInfo.userType !== 'externalUser'
    ) {
      $w.utils.showToast({
        title: '请先登录',
        icon: 'error',
        duration: 2000,
      });
      return;
    }

    // 2. 获取用户 ID 和手机号
    const userId = userInfo.userId;
    const phone = userInfo.phone;

    if (!userId || !phone) {
      $w.utils.showToast({
        title: '登录信息不完整',
        icon: 'error',
        duration: 2000,
      });
      return;
    }

    // 3. 显示加载状态
    $w.utils.showLoading({
      title: '正在验证身份',
    });

    // 4. 调用云函数
    const response = await $w.cloud.callFunction({
      name: 'agentAuth',
      data: {
        userId,
        phone,
      },
    });

    // 5. 获取云函数返回结果
    const result = response.result || response;

    $w.utils.hideLoading();

    // 6. 判断身份验证结果
    if (!result || !result.ok) {
      $w.utils.showToast({
        title: result?.message || '身份验证失败',
        icon: 'error',
        duration: 2000,
      });
      return;
    }

    // 7. 验证成功，进入代理首页
    $w.utils.navigateTo({
      pageId: 'u_dai_li_gong_zuo_tai',
      params: {
        agentId: result.agentId,
      },
    });

  } catch (error) {
    $w.utils.hideLoading();

    console.error('进入代理工作台失败:', error);

    $w.utils.showToast({
      title: error?.message || '进入失败',
      icon: 'error',
      duration: 2000,
    });
  }
}
```

# 本篇总结

本篇完成了代理工作台的身份验证基础。

实现过程可以概括为：

```text
用户登录 Web 应用
       ↓
点击代理工作台
       ↓
前端获取 userId 和 phone
       ↓
调用 agentAuth 云函数
       ↓
服务端验证当前调用者身份
       ↓
通过 user_id 查询代理记录
       ↓
没有绑定则通过手机号匹配
       ↓
服务端更新 biz_agent.user_id
       ↓
返回 agentId
       ↓
进入代理工作台
```

这套实现有几个重要特点：

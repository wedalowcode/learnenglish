# 前言

上一篇我们完成了管理应用的基础架构，实现了管理员和教务人员通过不同的工作台进入各自的业务区域。

从本篇开始，我们正式进入具体业务功能的开发。

首先搭建教师管理功能。

在英语教学平台中，教师是核心业务人员。后续的课程安排、课时记录、课堂反馈、教师结算等功能，都需要与教师建立关联。

因此，我们先从教师基础信息管理开始，完成教师信息的新增、查询、修改和删除。

本篇不使用云函数，也不编写复杂的自定义代码，而是充分利用微搭的数据模型和页面模板能力，完成一套标准的增删改查功能。

最终实现的功能包括：

- 教师列表：查看教师基本信息。
- 新增教师：录入教师资料。
- 编辑教师：修改教师基本信息。
- 删除教师：删除不再需要的教师记录。

本篇主要学习三个内容：

1. 如何在微搭中创建数据模型。
2. 如何为数据模型创建字段。
3. 如何根据数据模型生成标准的表格与表单页面。

# 一、回顾教师数据模型结构

在开始创建数据模型之前，先回顾一下前面设计的教师业务表。

在本项目中，教师对应的业务模型为 `biz_coach`。

为什么不直接使用微搭内置的用户表？

因为微搭的系统用户表由平台自行维护，不允许我们直接建立关联关系。而教师除了登录账号之外，还具有自己的业务属性，例如教师姓名、性别、入职时间、状态等。

因此，我们单独建立教师业务表，用来保存教师的业务信息。

前面设计的教师表结构如下：

| 字段名称 | 字段标识 | 字段类型 | 说明 |
|---|---|---|---|
| 主键 | `_id` | 系统字段 | 教师记录唯一标识 |
| 教师姓名 | `name` | 文本 | 教师姓名 |
| 手机号 | `phone` | 电话 | 联系电话 |
| 微搭用户ID | `user_id` | 文本 | 关联微搭认证用户 |
| 性别 | `gender` | 枚举 | 教师性别 |
| 状态 | `status` | 枚举 | 教师启用状态，枚举值为启用和禁用 |
| 入职时间 | `entry_date` | 日期 | 教师入职日期 |
| 备注 | `remark` | 文本 | 其他说明 |

这里有一个需要特别注意的字段：`user_id`。

它保存的是微搭认证体系中的用户 ID，用于将教师业务记录与实际登录账号对应起来。

**user_id 必须使用文本类型，不要创建成关联字段。**

原因是微搭系统内置用户表不允许我们直接建立关联关系。我们只需要将认证用户的 ID 保存为普通文本，后续就可以通过这个 ID 查询教师业务记录。

这也符合确定的身份绑定方案：

- 手机号负责首次身份匹配。
- `user_id` 负责后续身份关联。
- 教师业务信息保存在 `biz_coach` 中。
- 不直接依赖微搭内置用户表建立业务关系。

另外，`_id` 是数据模型的系统主键，由平台自动生成，不需要我们手动创建。

了解了数据结构，接下来进入微搭控制台创建数据模型。

## 2.1 进入数据模型

点击左侧导菜单的SQL数据模型，选择数据模型页签
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/5b802d65667540dd80e4c3db343063f6.png)

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/9868e2a9c8df4426b7fa2071424f141b.png)

数据模型名称填写：

`教师表`

数据模型标识填写：

`biz_coach`

建议从一开始就统一数据模型的命名规则。

本项目使用 `biz_` 作为业务数据模型的统一前缀，例如：

- `biz_coach`：教师
- `biz_agent`：代理
- `biz_parent`：家长

这样后续模型数量增加之后，也能够快速区分业务模型。

# 本篇总结

本篇完成了教师管理的基础功能。

整个过程没有编写云函数，也没有手动实现数据查询、创建、更新和删除逻辑，而是通过微搭数据模型和页面模板完成了标准 CRUD。

整个搭建过程可以概括为：

1. 根据业务需求设计教师数据模型。
2. 在微搭中创建 `biz_coach` 数据模型。
3. 按照业务字段创建对应字段。
4. 使用表格与表单页模板生成管理页面。
5. 将教师管理页面添加到教务工作区菜单。
6. 通过实时预览验证增删改查功能。

这里有一个重要的认识：

**业务系统并不是每个页面都需要从零开发。对于标准的数据管理场景，应该优先使用平台提供的数据模型和页面模板，把开发精力留给真正复杂的业务逻辑。**

当然，模板生成的只是基础 CRUD。

随着项目继续深入，我们还需要逐步完善教师管理，例如：

- 教师账号与业务身份绑定。
- 教师状态管理。
- 教师与学员之间的业务关系。
- 教师课程安排。
- 教师授课记录和课时统计。

这些功能会在后续章节中逐步实现。

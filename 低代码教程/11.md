# 一、本篇目标

上一节已经完成代理端“我的客户”页面，并通过关联查询实现了客户数据的动态筛选。

本篇继续完善客户管理功能，主要实现两个业务场景：

1. **客户报备**：代理新增客户时，系统自动识别当前登录代理，并将客户归属到当前代理名下。
2. **客户跟进**：代理可以在客户列表中打开跟进弹窗，填写沟通情况和下次跟进时间，提交后自动关闭弹窗并刷新列表。

本篇不重新开发客户报备表单，而是直接使用微搭根据数据模型生成的表格与表单模板。

对于客户跟进，我们单独创建跟进记录表，通过弹窗和表单容器实现。

完成后，代理可以在一个页面中完成客户报备、客户查看和跟进记录。

# 二、实现客户自动归属

## 2.1 为什么需要自动设置所属代理？

上一节创建客户表时，我们增加了一个关联字段：`agent_id`

这个字段关联代理表 `biz_agent`，用于表示客户属于哪名代理。

在管理端创建客户时，管理员可以手动选择所属代理。

但是代理端的业务逻辑不同。

代理登录后只能给自己报备客户，不应该让代理自行选择其他代理作为客户归属。

因此，新增客户时应该自动识别当前登录用户，并将客户的所属代理设置为当前用户对应的代理记录。

这里不需要重新开发云函数，也不需要重新实现客户新增表单。

我们可以利用微搭内置数据表查询和表单默认值完成。

## 2.2 创建代理信息查询

首先，在“我的客户”页面中创建一个内置数据表查询。

具体操作：

 打开代理端“编辑客户表”页面。在代码区点击新建
 ![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/cf3141c958c74413b025b2560064c243.png)

选择新建内置数据表查询
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/eaad74a03ab847249fa0e1bf49028144.png)
数据表选择代理表 `biz_agent`，触发方式选择入参变化时自动执行，方法选择查询单条

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/899bbfef45db4a68848a2e7bb8f1a95a.png)


设置查询条件。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/2c60cdf7f4a24010904d6f97aade2631.png)


查询条件配置如下：

| 字段 | 运算符 | 值 |
|---|---|---|
| `user_id` | 等于 | 当前登录用户的 `user_id` |

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/fe823d4add07415988a627a37e314b4b.png)


当前登录用户的 ID 从微搭认证上下文中获取。

这里要注意，查询的是代理表中的 `user_id`，而不是代理表的 `_id`。

查询结果就是当前登录用户对应的代理记录。

例如：

```text
当前登录用户
    user_id = USER_A
          │
          ▼
查询 biz_agent
    user_id = USER_A
          │
          ▼
返回代理记录
    _id = AGENT_001
    name = 张三
```

查询成功后，我们就可以使用查询结果中的数据标识 `_id`。

## 2.3 设置客户表单的默认所属代理

代理表查询已经配置完成，接下来修改客户新增表单。

进入模板自动生成的客户新增页面，找到表单容器中的“所属代理”字段。

这个字段对应客户表中的关联字段 `agent_id`。

选中该字段，在右侧属性面板中找到默认值配置。

点击默认值右侧的 fx，设置为刚才创建的代理信息查询结果中的数据标识。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/e5dfca358147428c97d9003e8736ec40.png)


表达式的逻辑是：

```javascript
代理查询结果._id
```

实际配置时，通过表达式编辑器选择查询结果的数据标识，不要手动猜测查询结果对象的层级。

这样，打开客户新增页面时，表单就会自动将当前代理作为所属代理。

例如：

张三登录后，代理查询返回：

```javascript
{
  _id: "AGENT_001",
  name: "张三",
  user_id: "USER_A"
}
```

那么客户表单的所属代理默认值就是：

```text
AGENT_001
```

李四登录后，查询结果会自动变成李四对应的代理记录。

因此，不同代理登录时，客户归属会自动变化。

## 2.4 验证客户报备

配置完成后，分别使用两个代理账号测试。

测试步骤：

1. 使用代理张三登录。
2. 打开“我的客户”。
3. 点击新增客户。
4. 填写客户姓名、电话、学生年级等信息。
5. 检查所属代理是否自动显示为张三。
6. 保存客户。
7. 返回客户列表，检查新客户是否显示。

然后使用代理李四重复测试。

预期结果：

| 登录代理 | 新增客户的所属代理 |
|---|---|
| 张三 | 张三 |
| 李四 | 李四 |

如果新增成功，说明客户归属已经可以自动识别。

# 三、创建客户跟进记录表

客户报备完成后，还需要解决日常客户维护问题。

代理与客户沟通时，需要记录沟通方式、沟通内容以及下一次跟进时间。

这些信息不适合全部放在客户表中。

例如，一个客户可能经历多次电话、微信和面谈。如果每次沟通都覆盖客户表中的跟进内容，就无法保留完整的历史记录。

因此，我们单独创建客户跟进记录表。

## 3.1 创建跟进记录数据模型

进入数据模型管理，创建新的数据模型。

模型名称：客户跟进记录表

模型标识：

`biz_customer_follow_up`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/d2bc6f99252c48b48e65d4c5e0e910d9.png)


字段设计如下：

| 字段标识 | 字段名称 | 字段类型 | 说明 |
|---|---|---|---|
| `_id` | 数据标识 | 系统字段 | 跟进记录唯一标识 |
| `customer_id` | 所属客户 | 关联关系 | 多对一关联客户表 |
| `agent_id` | 所属代理 | 关联关系 | 多对一关联代理表 |
| `follow_up_type` | 跟进方式 | 枚举 | 电话、微信、面谈、其他 |
| `content` | 沟通内容 | 多行文本 | 本次沟通情况 |
| `next_follow_up_at` | 下次跟进时间 | 日期时间 | 计划下次沟通时间 |
| `remark` | 备注 | 多行文本 | 补充说明 |

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/491cbe5b52ec4dcf827b31c819e7b18b.png)


其中有两个关联字段需要重点说明。

**customer_id：关联客户表**

每一条跟进记录都必须对应一个客户。

一个客户可以有多条跟进记录，因此客户与跟进记录之间是一对多关系。

**agent_id：关联代理表**

记录这次跟进由哪名代理执行。

虽然通过客户表可以间接找到所属代理，但单独保存跟进代理，可以更清晰地记录业务操作主体，也方便后续进行跟进工作量统计。

创建字段时，注意关联字段应使用微搭的关联关系类型，不要使用普通文本字段保存数据标识。

## 3.2 配置跟进方式枚举

`follow_up_type` 设置为枚举字段。

选项如下：

| 枚举值 | 显示名称 |
|---|---|
| phone | 电话 |
| wechat | 微信 |
| meeting | 面谈 |
| other | 其他 |

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/c46477d481bf41eba8bd4581355d5398.png)


这样后续统计时，可以直接按照沟通方式分类。

# 四、在客户列表中增加跟进操作

跟进记录表已经创建完成，接下来回到代理端“我的客户”页面。

## 4.1 添加跟进操作入口

选中客户列表中的表格组件。

在操作列中增加一个操作按钮：

**记录跟进**

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/8830109ee3f84caf9e88f7be6408dda9.png)


这个操作的作用是打开跟进弹窗，而不是直接跳转到一个新页面。

用户点击按钮时，需要把当前行的客户记录传递给弹窗表单。

因为弹窗需要知道当前正在跟进哪个客户，所以必须使用当前行数据中的 `_id`。

## 4.2 添加弹窗组件

在客户列表页面中添加一个弹窗组件。

弹窗标题设置为：记录客户跟进

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/55de8fe30dd94a948627cd6774f3497c.png)

弹窗中放置一个表单容器，作为跟进记录的录入区域。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/4c15af7778894b80bfc1f3bc3cadce73.png)


弹窗默认不显示，点击客户列表中的“记录跟进”按钮后再打开。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/f7b03eefe0d44da080a18201bf3e8e09.png)


## 4.3 添加跟进表单容器

选中弹窗内部的表单容器。

数据模型选择：

`biz_customer_follow_up`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/d9c2b30e6d27406db1ebc9fe87174142.png)


这样表单容器就会根据跟进记录表生成对应的字段。

根据实际页面布局，调整字段显示顺序：

1. 所属客户
2. 所属代理
3. 跟进方式
4. 沟通内容
5. 下次跟进时间
6. 备注

其中，所属客户和所属代理不应该让代理手动选择。

它们应该根据当前操作的客户记录和当前登录代理自动设置默认值。

## 4.4 配置所属客户默认值

选中表单容器中的“所属客户”字段。

找到默认值属性，点击 fx。

将默认值设置为弹窗组件入参的客户ID。

表达式逻辑：

```javascript
$w.modal1.openInfo.customeId
```

这样代理点击某个客户的“记录跟进”按钮时，表单就会自动绑定该客户。

## 4.5 配置所属代理默认值

同样选中“所属代理”字段。

默认值设置为当前代理查询结果中的数据标识。

也就是前面创建的代理信息查询返回的 `_id`。

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/f6ad8ac999dd423898d36c0efe187f36.png)


```bash
$w.modal1.openInfo.agentId
```

这样每条跟进记录都会同时关联：

- 当前客户。
- 当前代理。



这两个关联字段不需要代理手动填写。

## 4.6 调整表单字段

对于代理日常填写的字段，保留正常录入能力：

**跟进方式**

使用枚举选择，电话、微信、面谈、其他。

**沟通内容**

使用多行文本，设置为必填。

**下次跟进时间**

使用日期时间组件，根据实际业务设置是否必填。

**备注**

用于补充记录，可以设置为非必填。

如果微搭表单容器支持隐藏字段，可以将所属客户和所属代理设置为隐藏字段，避免代理误操作。

如果当前组件不支持隐藏，则可以设置为只读或不允许修改。

# 本篇总结

本篇完成了代理端客户管理的两个基础功能。

第一个功能是客户自动归属。

我们没有重新开发客户新增页面，而是利用模板生成的表单容器，通过内置数据表查询获取当前代理记录，再将代理记录的数据标识配置为所属代理字段的默认值。

第二个功能是客户跟进。

我们创建独立的跟进记录表，通过关联字段记录客户和代理，在客户列表中增加操作入口，使用弹窗承载跟进表单。

整个过程没有编写复杂的自定义代码，主要通过微搭的数据模型、内置查询、表单容器、弹窗和组件事件完成。

这里有一个重要的业务设计原则：

**客户基础信息与客户跟进记录应该分开保存。**

客户表记录客户当前状态，跟进记录表保留每一次沟通的历史。

这样后续无论是统计代理跟进数量、分析客户转化率，还是查看客户完整沟通历史，都有清晰的数据基础。

下一篇可以继续完善客户管理，例如客户列表的跟进提醒、逾期跟进筛选，以及客户详情中的历史跟进记录。
